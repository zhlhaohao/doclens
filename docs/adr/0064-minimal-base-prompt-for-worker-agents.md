# ADR-0064: 框架提供「精简基础提示词」变体（无人值守工作代理）

- 状态：已接受
- 日期：2026-11-25
- 关联决议：ADR-0053（框架宿主注入——本变体是框架的中性扩展，不含宿主名）、ADR-0063（数字员工技能预加载与工具授权）

## 背景

planify 的通用系统提示词（`build_system_prompt`）与每轮头部注入是为**交互式对话助手**设计的。宿主接入「无人值守的工作代理」——有固定工具集、技能预加载、无人可问——时，通用提示词有四处会误导它：

| 段 | 对工作代理的问题 |
|---|---|
| Skill vs Tool priority：「匹配技能时必须先 `load_skill`」 | 代理没有 `load_skill`，技能已预加载——会去找不存在的工具 |
| 「用 TaskCreate 管理工作」 | 任务管理类工具对代理是禁用的 |
| 外部访问门禁：「需要外部路径先 `ask_user_question`」 | 代理无人可问——挂到超时 |
| 头部注入：技能清单「available with the Skill tool」+ `agent.md` + 临时文件目录 `<数据目录>/tmp/<session>/` | 清单与 agent.md 是对话助手语境；临时目录在宿主为代理划定的可写范围之外 |

## 决策

`StreamingAgent` 增加基础提示词变体选择（默认 = 现状）。**精简变体**：只保留「系统约定 / 工具使用规则 / 环境信息 / 门禁当前配置（去掉向人询问的流程）/ 输出简洁」；剔除任务管理引导、技能加载引导、语气风格。头部注入同步精简：不注入技能清单与 `agent.md`；临时文件目录可由宿主指定（宿主可把它指向代理的可写范围内）。

- **中性扩展**：变体只描述「面向工作代理的精简基础提示词」，不出现宿主名、不读宿主配置命名空间——任何宿主接入专用工作代理都能用。
- **默认不变**：现有宿主行为零变化，仅显式选择精简变体时生效。

**否决**「专属提示词里打补丁（忽略上文关于 load_skill / TaskCreate / ask_user_question 的指示）」：靠提示词覆盖提示词，不可靠；且门禁规则与临时目录是按环境动态生成的，补丁要跟着变。

**否决**「完全替换系统提示词」：工具使用规则（怎么调 read_file、怎么写文件）是框架对工具的说明书，整体替换等于把它的维护责任转嫁给每个宿主。

## 后果

- 这是数字员工唯一需要动 planify 的地方；planify 独立发版，doclens 发版须带对应 planify 版本。
- 专属提示词以**追加**方式挂在精简基础提示词之后。
- 宿主侧（doclens）同时不再为工作代理拼接知识库指导、长期记忆纪律、引文规范——这些是对话助手的表现规范，与工作代理身份不符。
