# ADR-0051：吸收 luobo-ppt 的确定性设计规则（HTML 路线不变）

日期：2026-10-29
状态：已接受

## 背景

对比分析了商业级技能 `luobo-ppt`（7906 行 Python、35 版式、14 风格、双路线生成/美化）。其核心优势不在产物体量，而在**把「审美」尽可能转成确定性规则**：字号阶梯、容量表、强调色上限、对比度预算、孤字规避。这些规则让「AI 做的 PPT 丑」从主观问题变成可机器判定的问题。

同时确认两条边界：**不产出 .pptx**（ADR-0050 已定 HTML 路线）、**不引入其 AI 生图客户端**（我们已有即梦）。

## 决策

1. **版式容量写进资产**：`data-cap` 属性随版式 HTML 走（而非独立 JSON 或代码常量）。延续「版式即资产、零代码扩展」原则，容量与结构同文件不易漂移。
2. **写稿期预检前置**：新增 `check` 子命令（秒级、不渲染），检查容量/大纲/结构/密度/主题对比度，产出**幽灵稿** `<名>-outline.md`。纪律：check ERROR 清零再 build。动机：容量的价值在「早发现」，等渲染+视觉验收（分钟级）才发现等于白跑。
3. **字号阶梯替代连续缩放**：autofit 从二分连续值改为在 `body 22/20/17/15/13` 五档上遍历取档（`--fit` = 1/.909/.773/.682/.591）。全 deck 只剩 5 种缩放态，同级标题跨页一致。代价是可能比连续缩放少装一点内容——这正是想要的：逼内容精简而非硬塞字号。
4. **孤字用 CSS 原生规避**：`text-wrap: pretty`（Chrome 117+），不引入 JS 换行计算。
5. **颜色硬预算**：强调色单页 ≤3 处 / ≤8% 面积；对比度 WCAG 正文 4.5:1 主色 3:1。前者在几何自检里量（浏览器侧取 --c-accent 比对），后者在 check 时算。
6. **图标集**：81 个内置 Lucide 风格 SVG（`assets/icons.json`），`<i data-icon="name"/>` 进入行内白名单，`currentColor` 随字色。**不做关键词自动匹配**（中文关键词匹配准确率低，乱配图标比没图标更糟）；版式可留默认图标位，LLM 显式指定优先。
7. **五维自评并入验收**：整册五维（统一/层级/细节/传达/节奏）由整册截图一次性评审，**不阻断交付**（阻断仍靠 high 问题与单页 score<70），但必须在交付说明里报分与最弱项。
8. **风格库 4 → 8**：新增 swiss-grid / ink-magazine / mint-fresh / warm-orange，全部通过对比度校验（mint-fresh 的 accent 因此从 #F2734A 调到 #E4572E）。

## 后果

- 优点：写稿期就能挡住 80% 的「装不下」问题；排版整齐度靠阶梯保证；颜色问题靠预算确定性拦住，不必等视觉模型模糊吐槽。
- 代价：`check` 多一个步骤要记（SKILL.md 已写明纪律）；阶梯跳档可能比连续缩放少装一点内容（有意）。
- 有意不做：luobo 的 AI 生图客户端与程序化插画兜底（即梦已覆盖前者；后者在配了生图模型时边际价值低）、旧 pptx 美化路线（明确不要）、关键词自动配图标。
