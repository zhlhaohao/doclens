# ADR-0038: 会话导出导入——全保真单会话 JSON

- 状态：已接受
- 日期：2026-10-07
- 关联决议：ADR-0026（压缩即事实——边界条目必须随导出）、ADR-0027（回退即事实——死段照导的依据）、ADR-0034（对话图片——base64 随 payload 走）

## 背景

开发会话（chat 会话）承载着跨轮积累的任务上下文：用户意图、已做决策、
工具调用轨迹、压缩摘要。换机器或换 doclens 实例时，这些记忆锁死在
各机自建的 `sessions.db`（`.cortex/` 本地状态目录，被 Git 同步刻意
排除，ADR「同步范围」），无法随知识库内容走。

需求：**把一个开发会话的记忆转移到其他 agent（另一 doclens 实例）**，
转移后可续聊——上下文完整回放进 LLM，前缀缓存语义不丢。

## 决策

### 导出 = 全保真单会话自有 JSON

- **粒度**：单会话（chat-view more 菜单「导出会话」）。不做全量
  打包（将来可加）；search 历史不在范围。
- **内容**：sessions 行（title/mode/starred/时间戳…）+ **全部
  session_items 原样**——含 raw_messages、compacted（压缩边界）、
  rewound（回退边界）、usage、skill_context，**含死段与被压缩截断的
  旧条目**。不做活投影过滤。
- **不导**：rewind_snapshots（引用 `.cortex/rewind/` 机器本地文件
  备份，跨实例无意义；对话侧 rewound 边界在 session_items 里照导）、
  auth_sessions（登录凭证）。
- **载体**：浏览器下载（`Content-Disposition: attachment`），文件
  名含标题 slug + 日期。不写知识库目录、不进索引、不参与 Git 同步。
- **API**：`GET /api/sessions/{id}/export`，直读 sessions +
  session_items 原始行拼格式（绕过展示层投影模型）。
- **格式**：顶层 `format: 1` 版本号。

### 导入 = 文件选择器上传 + 同 id 跳过

- **入口**：历史会话列表 header「导入」按钮；文件选择器选 JSON
  （无拖拽/粘贴）。
- **冲突**：目标库已有同 id 会话 → **跳过并提示「会话已存在」**
  （幂等、防双份；会话身份 = id）。
- **校验**：**结构校验不语义校验**——版本号、必填字段、items 字段
  类型（seq/kind/payload-json）；payload 内部语义交回放层容错
  （`_sanitize_tool_pairing` 本来就会处理）。失败整体 400，不部分导入。
- **版本**：只认已知版本，不认识的 `format` → 400「文件版本不支持」。
- **衔接**：toast 报告（导入 n / 跳过 n）+ 列表刷新即止，不自动进入
  会话；created_at/updated_at **保留源值**（排序如实反映会话时序）。
- **信任**：前端选文件后弹确认（显示标题/条目数）才上传；后端 body
  上限 50MB；鉴权走现有 auth 闸门。信任模型对齐既有惯例——「操作者
  可访问知识库即可信」，导入会话与往知识库放一个 md 文件的风险面
  等同（同技能安装的「确认时一次授予」）。

### 截断导出 = 导出到此为止（2026-10-29 增补）

长会话整段导出→导入会把超长上下文原样搬到新会话。为此在 **user 气泡
操作行**增加「导出到此为止」按钮（`export-upto` 事件 → chat-view 调
`GET /api/sessions/{id}/export?upto_seq=N`）：

- **范围**：只导 `seq ≤ 锚点` 的条目——锚点这条 user 消息**本身在导出
  范围内**（「到此为止」的字面义）
- **锚点校验**：须为活 `message_user`（与回退锚点同口径，`is_live_anchor`）；
  无效 → 400 `INVALID_ANCHOR`；仅 chat 会话（search 会话 400）
- **身份**：产物是**派生快照**而非源会话本体——**新 id** + 标题后缀
  「（导出至 N 条消息）」。沿用同 id 会被导入端「同 id 跳过」静默吞掉
  （同实例导入即完全失效），故与全量导出的「同 id 转移」刻意区分
- **重算**：`message_count` 按截断后的活投影重算（前缀内的 rewound 边界
  照常生效）；`updated_at` 取锚点条目时间；`starred` 不继承（同 duplicate）
- **文件名**：标题 slug（含后缀）+ 日期；WebView 原生下载由 H5 给名字，
  截断导出追加 `-upto`，避免与同标题全量导出同名覆盖
- 不传 `upto_seq` 时逐字保持原全量导出的行为（向后兼容）

### 其他裁定

- **对话图片随导**：message_user payload 里的 images（base64）照常
  进导出文件，导入后完整恢复（接受文件数 MB 级）。
- **流式生成中不限制导出/导入**：导出是纯读（最多末轮不完整可接受）；
  导入与生成分属不同会话，写库有全局锁。

## 否决的替代方案

- **Markdown 对话转录（通用 agent 格式）**：任何 agent 都能读，但
  Markdown 是「给人读的投影」——丢工具调用结构、丢边界事实，导入后
  无法续跑（回放语义不存在），只能当一次性参考材料。记忆转移的本质
  是「下一个 agent 续聊」，续跑能力是硬需求。否决；将来若需要给人
  分享可另做「导出转录」功能，与本次互不替代。
- **对接特定 agent 私有格式**（Claude Code JSONL 等）：可直续跑，但
  绑定外部格式、各家无标准、随对方演进而腐烂。否决。
- **只导活投影**（project_live_items 过滤后）：文件更小，但等于导出
  时物理化截断——压缩边界、回退边界的事实被销毁，违背 ADR-0026/0027
  「边界即事实、库恒 append-only」的哲学，导入后与源会话不再是同一
  对象。否决。
- **导入覆盖同 id** / **每次重建 id**：覆盖会静默丢失目标侧续聊
  （违背 append-only）；重建 id 使同一文件导两次出双份、会话身份丢失。
  否决，跳过最诚实。
- **导出落盘知识库目录**（借 Git 同步走到对端）：文件进索引/搜索、
  会话双份数据（DB + 文件）。记忆转移 ≠ 知识沉淀，会话不是知识库
  文档；真要沉淀应人工总结成文档。否决。

## 后果与风险

- **格式成为兼容负担**：导出文件一旦流通（用户保存、转发），旧版
  doclens 遇新版格式会拒绝——这是版本号机制的有意行为（明确拒绝
  优于静默乱数据），升版时需在导入端做向后兼容分支。
- **文件含完整对话明文（含 base64 图片）**：导出文件脱离 DB 保护，
  用户自行负责其存放与传递；与「导出 = 下载」的载体决策一致。
- **跨实例语义漂移**：导入会话若引用源实例的技能（skill_context 落
  库的 body 照常回放，无碍）；但工具调用轨迹里的路径指向源机器的
  工作目录结构——续聊时 AI 需自行适应（与把会话交给新 agent 的
  本质一致，不额外处理）。
