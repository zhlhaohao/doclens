# 0045 — Web 搜索结果按文件分组（一命中一行，替换扁平节点卡片流）

日期：2026-10-18
状态：已接受

## 背景

Web UI `/api/search` 与 `/api/grep` 原返回**扁平节点列表**（一节点 = 一张
result-card：整段 markdown 渲染的 snippet + 评分百分比），前端垂直卡片流。
实测四个结构性问题：

1. **卡片内零命中反馈**：snippet 是节点前 `max_context_lines`（默认 5）行，
   命中词常不在其中；`highlights` 字段恒为 `[]`（死代码）。用户无法在列表层
   判断「为什么命中、值不值得点」。
2. **评分是噪声**：like 降级源固定 0.5、ripgrep 源固定 0.0，前端显示
   「评分: 50%」「评分: 0%」误导；composite 分对最终用户无语义。
3. **同文件命中碎片化**：同一文件的多条命中（每文档最多
   `max_nodes_per_doc`=1000 个节点）散落列表各处。
4. **md 渲染片段占地大**：一张卡 4-8 行，一屏看不到几个文件。

## 决策

**结果按文件分组聚合，组内一条命中一行**（IDE 搜索结果形态）：

- **响应契约改为 `GroupedSearchResponse`**（破坏性变更）：
  `groups: FileGroup[]`，每个 FileGroup = `path + best_score +
  total_matches + matches[]`；每个 MatchItem = `line + text + spans`
  （单行文本 + 命中字符区间，≤200 字符，超长以首命中为中心截断）。
  旧 `SearchResponse`（扁平 `results: SearchResult[]`）退役。
- **分页单位从节点改为文件**（默认 20 文件/页）；文件按组内最佳命中
  综合分降序；计数文案「N 个文件 · M 处命中」（`total` = 文件数，
  `total_matches` = 命中行总数）。
- **命中行定位在后端做**（`web_v2/api/_grouping.py`）：关键词源对节点文本
  逐行跑字面子串匹配（大小写不敏感），grep 源跑正则词项（非法正则退字面），
  产出 `(行号, 行文本, 命中区间)`。行号 = `node.line_start + 行内偏移`。
- **文件卡头部** = 文件名（大）+ 目录（小字）+ 命中数徽标；**不展示评分
  百分比**（排序仍用综合分，只是不再给人看）。
- **交互**：点头部 = 展开/收起组内命中行；点命中行 = 预览定位该行
  （detailStack 载荷从 SearchResult 收窄为 `SearchHit {path, line}`）。
  默认展开前 3 行，余下折叠「+N 更多命中」。
- **降级源同构**：LIKE（无行号）→ 单行卡，行号区显示「—」，点击顶部打开；
  grep path 命中 → 文件组 kind="path"，头部「路径」徽标、无命中行。
- **每文件命中行下发上限 50**（`MATCHES_PER_FILE_CAP`）：徽标显示真实
  `total_matches`，超出部分 truncated 标记 + 前端注明「仅显示前 50 处」——
  防单文件上千行命中撑爆响应。
- CLI/TUI 不受影响（走同一 `score_and_rank` 管道但各自 formatter）。

## 理由

1. **命中行定位绕不开后端**：snippet 前 5 行不含命中词，前端从现有字段
   无法可靠重建命中行；grep 词项是正则片段，前端高亮不可靠。分组/排序/
   分页随之留在后端（前端聚合会让「按文件分页」名存实亡——一页 20 节点
   可能只属于 1 个文件）。
2. **扫读效率**：单行命中的信息密度远高于 md 段落卡片；文件分组把
   「同文件多命中」收拢为一次视觉定位；md 渲染移出列表、只留预览栏
   （列表管扫读定位，预览管阅读）。
3. **诚实呈现**：固定分（0.5/0.0）伪装成百分比是误导；命中数徽标
   「N 处命中」是对用户真正可行动的信息。

## 后果

- 前端 `result-card.ts` 删除，新增 `file-card.ts`；`search-results.ts`/
  `search-view.ts`/store/types 适配；测试同步重写（file-card.spec 新增 6 例，
  search-view 系列 34 例全绿）。
- rg 合成节点（词窗截断）的行号是近似值——预览侧本就以行区间展示，接受。
- 单文件命中 >50 时组内不可见（列表层），预览侧匹配导航仍可遍历全部命中
   ——可接受的分层。
