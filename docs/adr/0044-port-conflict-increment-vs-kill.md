# 发行版端口冲突递增、开发版杀占用者

`launch_app` 的端口冲突处置按发行通道分野：开发版（editable/源码，经 start-app 按 worktree 算专属端口）杀占用者复用原端口；发行版（site-packages）不杀进程，从基准端口递增找第一个空闲口启动，终端打印实际端口。

动机：开发版端口是 worktree 专属（`CORTEX_WEB_PORT + N`），占用者几乎必然是本 worktree 旧实例，杀它是预期运维动作、且递增会让「按目录名算端口」的健康检查约定失效。发行版跑在用户机器上，基准端口（如 8000/7860）的占用者可能是任意无关服务，杀进程是事故；用户并行跑多个知识库实例也是合法场景，递增让两者共存。

否决方案：发行版也杀端口（误伤无关服务）；两版都递增（破坏 worktree 端口可预测性，AI 代理重启后无法按目录名反推端口验证）。
