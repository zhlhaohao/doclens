# 对话输入框图像支持与视觉路由

Status: accepted（2026-10-05）

对话输入框支持粘贴/选择/拖拽图像随消息发送；对话 LLM 支持视觉时图像原生进上下文，不支持时拦截发送并引导用户切换模型。**不引入视觉 API 兜底转写中间态。**

## 决策

1. **对话图片（会话级附件）**：粘贴图不落知识库目录、不进索引、不参与 Git 同步、不进视觉解析队列；随会话存储于 sessions.db，随会话删除级联消失。与既有「图像文件」（知识库文件）、「内嵌图片」（文档提取）构成三种互斥图像形态。
2. **视觉路由 = LLM 预设 `vision` 能力位**：LLM 预设新增显式布尔字段（默认 false，保守——未声明视为不支持）。true → image block 原生直通对话模型（provider 层既有通路：Anthropic 原生 / OpenAI-compat 经 tool_translator 译 image_url）；false → 前端发送时拦截（消息不发、输入与附件保留），提示对话框 +「前往设置」跳模型 tab 手动切换（预设热生效，切完回原页重发）。
3. **消息附件形态**：`message_user` 落库 payload = `{"content": 文字, "images": [{data, media_type}, …]}` 平级数组——**无图消息与旧格式逐字节相同**，旧会话/幂等判断/回退锚点零改动；images 非空时回放才组装块数组发给 LLM。文字必填（空文本不发送）；图是附件，单轮 ≤4 张，格式白名单 png/jpg/jpeg/webp/gif，粘贴即前端压缩（最长边 1600px、q80，复用日记照片参数）。
4. **上下文三件套**：
   - **回放不衰减图片**：历史图片永驻回放投影，保持与历史真实请求逐字节一致（prompt 前缀缓存的存亡线）；
   - **token 估算按像素**：`estimate_tokens` 对 image block 按像素面积估（数千 tokens/张，与 API 真实计费同量级），不数 base64 字符（防单图误估数十万、击穿 auto-compact 阈值判断）；
   - **compact 转录剥图**：压缩转录把 image block 换 `[图片]` 占位（同 LLMTracer `_redact_images` 既有模式），历史图片退役搭压缩边界的车（本就是已接受的缓存重置点）。

## Considered Options（被否决方案）

- **视觉 API 兜底转写（对话模型不支持视觉时调独立视觉 API 把图转文字注入）**：**否决**——盲转写丢提问语境细节（截图/UI 问答恰是关键场景）；双模型两段式交互复杂；调用时机（粘贴时/发送时）各有浪费。用户明确表态不考虑转写方案。
- **回放年龄衰减（仅保留最近一轮图片，其余换占位）**：**否决**——第 N 轮实发带图、第 N+1 轮回放剥图 → 从该图起前缀逐字节失配 → 每轮全量 cache miss。省 2K 图 token、赔几十万级全前缀缓存重算，负收益。违反「回放投影」铁律（ADR-0026 建立的逐字节一致原则）。
- **保留最近 K 轮（K=3）**：**否决**——同样破坏前缀缓存，且 K 无从标定。
- **不衰减不估算，纯靠 auto-compact 兜底**：**否决**——阈值窗口内图片全程重放，且现有 `len(json)//4` 估算会把 base64 数成文本（单图 ~15 万"tokens"），压缩阈值误判。
- **发送试探 + 失败降级**（默认带图直发，报错再降级）：**否决**——多数 OpenAI-compat 网关静默接受 image_url 不报错、模型实际看不见图，产生无从检测的瞎答。
- **内置模型能力表**（model_id 前缀匹配）：**否决**——随模型迭代必然过时，无人维护。
- **content 升级为块数组**（message_user 落库直接存 LLM 同构块数组）：**否决**——所有消费方（回放分派/前端展示/回退回填/get_detail）都要双形态兼容，改动面大；平级 images 数组达成同样目标且无图路径零风险。
- **粘贴即预转写 / 粘贴时拦截**：**否决**——L1 场景不需要转写、粘贴后可能不发；粘贴自由、发送时统一判定。
- **对话框内直接切换 vision 预设**（L3 引导内嵌预设下拉一步切）：**否决（本期）**——对话页需复刻预设切换逻辑 + 空态 + 失败回滚；手动跳设置为起步，对话框留位作后续增强。

## 增补：视觉探测（2026-10-05，行为学实测能力位）

ADR 正文「能力位 = 用户显式声明（默认 false）」的自动化增强（正文预留：「将来想自动化也可加『探测视觉』按钮」）——声明制不变，探测把声明依据从猜测变为实测。

**机制**：`POST /api/presets/probe-vision`（请求体同 ProbeMaxTokensRequest 形态：protocol/base_url/model_id/api_key?/preset_id?，密钥留空回退预设已存值）。后端程序合成一张随机密码串图（PIL，红底白字 512×512、密码串 5 位去易混字符随机生成），经 provider 既有 image 通路（anthropic 原生 block / openai_compat 译 image_url）问模型「图中字母数字序列」，`max_tokens=32`，判定：

| 回答 | 判定 |
|------|------|
| 文本包含密码串（去空格/标点、容错大小写） | 支持 |
| API 报错（400/415/unsupported 等） | 不支持 |
| 正常返回但不含密码串 | **不支持**（静默吞图——正是本 ADR 否决「发送试探」时点名的不可检测类，行为学探测是唯一能抓住它的手段） |
| 连接/鉴权失败 | 探测中止（ProbeError，不判定） |

**交互**：预设表单「支持视觉」旁「探测视觉」按钮（对齐「探测上限」先例）→ 探测中状态 → 结果**回填表单 vision 字段**（支持→true/不支持→false）+ 结论文案，**不自动保存**——用户可否决。新建态用表单当前值探，编辑态密钥留空（不改动）时回退 preset_id 取已存密钥。

**纪律**：单次不重试（对齐判向旋转「失败不重试」哲学——按钮便宜，用户重按即可）；随机化密码串防训练记忆蒙对（读图成为唯一信息来源）；只探对话模型（视觉预设无关）；每次探测花 ~1K 输入 tokens（比二分探测 max_tokens 的 ~18 次调用便宜一个量级）。

## Consequences

- **planify 改动**：`estimate_tokens` 识别 image block 按像素估；compact 摘要转录剥图换占位；`run_stream` 接受可选图像参数（有图时本轮 user 消息构造块数组，无图保持纯字符串——零破坏）。
- **预设体系**：`PresetCreate/PresetUpdate/Preset` 加 `vision` 布尔（仅 kind=llm 有意义），设置页模型 tab 加开关，status API 暴露当前激活预设能力位（前端拦截判定用）。
- **chat API**：`ChatRequest` 加 `images` 数组（b64 + media_type，≤4，后端同样校验上限/白名单）；`ensure_message_user` 存 images；`get_chat_history` 回放 images 非空时组装 `[image×N, text]`。
- **前端**：input-box 加粘贴/📎/拖拽三入口 + 缩略图暂存行（× 删除）；发送键条件改为「文字非空」（图不再单独激活发送）；chat-view 发送前判 vision 位拦截；历史气泡读 images 画缩略图（点击全屏复用 image-viewer）；回退锚点回填 = 文字回输入框 + 图回暂存区。
- **会话中途从 vision 模型切到非 vision 模型**：回放照常带图，下一轮 API 报错按既有 LLM 错误浮出，不做历史预检（预设热生效是既有语义，不为边缘场景加扫描）。
- **带宽固有成本**：图片在上下文期间每轮请求体携带其 base64（API 无"引用已见图片"机制）；4 张 × ~600KB 已封顶，属保持缓存的接受代价。
- **斜杠技能/技能会话允许带图**（文字必填保证信封完整）；LLM Trace 天然兼容（`_redact_images` 既有）；断开续跑/429 无特殊处理（图在首轮 user 消息，重发同一份）。
