# ADR-0063: 数字员工的技能预加载与工具授权

- 状态：已接受
- 日期：2026-11-25
- 修订：§1「技能预加载」被 ADR-0065 取代（全部技能按需加载，`load_skill` 由白名单 handler 校验；禁用工具清单移除 `load_skill`；技能为内部技能库中的技能）
- 关联决议：ADR-0016（对话技能直发——员工入口与之并列、行为相反）、ADR-0021（外部访问门禁——写入边界沿用同一纵深防御定位）、ADR-0062（数字员工实体与评审循环）

## 背景

数字员工是无人值守的自驱循环：工具授权错了会挂死或失控，技能没加载会干不好。现有机制两个口子都不适合直接复用：

- `load_skill` 没有白名单——放开它等于技能授权形同虚设，模型能加载任意技能。
- 通用系统提示词在教模型「匹配技能时先 load_skill」「用 TaskCreate 管理」「需要外部路径先 ask_user_question」——数字员工没有这些工具，照搬会让它寻找不存在的工具、或挂起等待无人应答的确认。

## 决策

### 1. 技能白名单 = 预加载，不给 `load_skill`

> **已被 ADR-0065 取代（2026-11-26）**：预加载会让员工在工作回合就看到评审技能的方法；改为全部按需加载，白名单由 `load_skill` 的 handler 校验。本节保留作历史记录。

派活开始时，白名单内技能的正文**直接注入系统提示词**；白名单外的技能不进技能清单、不可加载。数字员工的技能白名单语义是「上岗时已掌握的技能」，不是「可以去查的范围」。

**否决**「`load_skill` + 白名单校验、按需加载」：依赖模型想到要加载，团队 DAG 的真机验证里 Bot 常不加载技能就开干。数字员工是定义清楚、无人值守的实体，技能应当是固定能力，行为可预期。代价是技能正文占用系统提示词长度，对一次派活可接受。

### 2. 工具授权：白名单 − 黑名单，禁用工具强制剔除

- 白名单 = 「只许这些」，空 = 全部；黑名单 = 「这些永远不许」，空 = 不排除；并存时**黑名单永远优先**。
- **禁用工具**对全部员工无条件不可用（`load_skill` 已于 ADR-0065 移出本清单），配置里写了也忽略：向人提问（无人可答，挂到超时）、子代理 `task`（不受写入边界约束，是绕过边界的后门，且不受兜底切换保护）、后台任务（脱离回合）、`load_skill`（技能走白名单）、团队协作与手动压缩类。

**否决**给数字员工开 `task` 子代理：大范围调研场景它很有用，但它绕过写入边界。本期保持边界干净。

**否决**MCP 工具按服务器整包授权：角色 = 用户授予的权限包，通配会让新接入的任何 MCP server 自动对员工可用。按具体工具名授权。

### 3. 新员工预填安全默认

工具白名单默认 = 读文件、搜索、写文件、编辑与知识库工具；**shell 与全部 MCP 工具不在默认内**，须用户显式勾选。多数员工（写报告、填模板）不需要 shell。

### 4. 写入边界的定位：纵深防御，不是沙箱

写入边界对结构化文件工具（write/edit）是硬保证；对 shell 只是命令文本扫描（脚本内部拼接的写入会漏检）；对 MCP 工具**完全管不到**（独立进程写文件，可写范围由各服务配置决定）。授予员工 shell 或有写入能力的 MCP 工具即接受此风险，授权界面须明示。派活说明仍要求产物写进产物目录，评审也只看产物目录——写到别处等于未交付，员工有动力写对地方。

## 后果

- 员工的提示词结构 = **精简基础提示词 + 专属提示词**（见 ADR-0064）。专属提示词以追加方式生效，不做整体替换——工具使用规则员工仍需要。
- 员工级思考深度（默认跟随全局）：简单任务（格式转换、按模板填充）不值得思考开销，复杂任务需要；在全局档位之上加员工级覆盖，不加更细粒度。
- 工作模型必填、评审模型可空（空则工作模型自评）；两者都存预设引用，预设被删时员工标红「模型预设缺失」、不可派活。
