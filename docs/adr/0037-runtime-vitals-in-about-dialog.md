# 关于弹窗运行情况面板

「关于」弹窗从"版本号（+开发模式构建调试块）"扩展出**运行情况（Runtime Vitals）**分区：运行时长、内存 RSS、线程数、对象数、错误数、GC 回收次数六项指标，**所有模式可见**（发行版用户同样受益——反馈"卡了/崩了"时一张关于页截图带走排障数据，这是与"仅开发模式的构建调试信息"的有意分层：构建信息只对开发者有意义，运行情况对最终用户同样有意义）。

## 决策

1. **指标集 = 核心六项**（uptime / RSS / threads / objects / errors / GC collections），覆盖"卡了/崩了/内存涨了"排障场景；否决全家桶（CPU%、句柄数、asyncio 任务数等——弹窗变任务管理器，CPU% 还需采样窗口）与最小四项（丢 GC/uptime 的廉价信息）。
2. **错误数 = 进程内计数器**：`logging.setLogRecordFactory` 全局记录工厂累计 ERROR/CRITICAL 条数（doclens 宿主侧安装，对所有 logger 生效、零 I/O）。口径 = **本次运行累计**；否决"当日日志文件 grep 统计"（每次打开扫最多 20MB 文件，且多进程写同一文件混入 TUI/MCP 的错误）。
3. **数据通道 = 扩展 `/api/health`**：与版本号同源一次 fetch 拿齐；该端点本就免鉴权（登录页探活），localhost 单用户场景暴露内存/线程数可接受；否决新建 `/api/runtime`（多一次请求 + 登录前不可见 + 401 降级分支）。
4. **刷新 = 打开期间每 5 秒轮询**：弹窗 open 时起 `setInterval`、Esc/关闭即清；运行数据看快照意义有限，用户盯着就是为了看变化。
5. **排版 = 「运行情况」分区 2 列 × 3 行紧凑网格**：六项排成小卡片网格而非逐行堆叠（弹窗不拉长），数字沿用等宽字体。

## 实现口径

- 内存/线程优先 psutil（win_arm64 wheel 已验证，加入 pyproject 依赖）；import 失败降级显示"不可用"（不 crash）。
- `threading.active_count()`、`sys.getallocatedblocks()`、`gc.get_stats()` 为标准库兜底项（psutil 缺席时线程/对象数仍可报）。
- 指标只反映 GUI 主进程；MCP stdio 子进程不聚合（弹窗语义 = 本应用进程）。
- 现有开发模式调试块（前端构建/bundle/代码新旧）原样保留，新分区独立。
- 错误计数器不区分来源 logger（uvicorn/watchdog 的错误同样计入——用户视角"应用出了多少错"不分家）。
