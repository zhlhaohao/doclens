# ADR-0052: 删除对话对——轮级裁剪会话历史

- 状态：已接受
- 日期：2026-10-29
- 关联决议：ADR-0026（压缩即事实）、ADR-0027（回退即事实）、ADR-0038（会话导出导入）

## 背景

长会话里无用轮次（跑偏的尝试、一次性问答、工具失败后的重试）会一直
留在 `session_items` 里，每轮都进 LLM 回放上下文，白烧 token。现有两条
清理路径都不对口：

- **回退（ADR-0027）** 是「回到这里重来」——锚点及其后**全部**折进死段，
  只能砍尾部，砍不了中间；
- **压缩（ADR-0026）** 是「整段摘要」——粒度太粗，且要付一次 LLM 调用。

需求：在对话流里**就地删掉某一轮**，前后轮次照旧。

## 决策

### 入口与粒度

- **入口**：user 气泡操作行「删除这一轮」按钮（与重问/导出到此为止/回退
  同排），点击弹确认框（显示锚点摘要 + 本轮消息数 + 不可撤销警告）。
- **粒度是整轮**（对话对）：锚点那条 `message_user` 起，到**下一条**
  `message_user` 之前（或会话末尾）的全部条目——含 `raw_messages` /
  `tool_trace` / `message_ai_raw` / `message_ai` / `usage` / `microcompact`，
  以及紧邻锚点之前由本轮注入的 `skill_context`。
  只删一半会让 `_group_turns` 把 user 与 assistant 拆散，回放语义断裂。

### 约束

- 锚点须为**活** `message_user`（死段内不可删，与回退锚点同口径）；
- **范围内含 `compacted` / `rewound` → 拒绝删除**（400）。这两类是历史级
  事实：删掉压缩边界会让边界前的历史「复活」，删掉回退边界会解除死段。
  正确处理方式是回退或重新压缩，不是删轮；
- 仅 chat 会话；**流式生成中 409**（本轮快照未固化，与回退/压缩同锁口径）；
- 删除后 `message_count` 按活投影重算（死段不计），刷新 `updated_at`；
- `rewind_snapshots` 不删（引用 `.cortex/rewind/` 机器本地文件备份）：
  被删锚点的快照随锚点失效不可达，会话删除时级联清理。

### 为什么是物理删除而不是再落一条边界

ADR-0026/0027 的哲学是「边界即事实、库恒 append-only」——压缩与回退都是
**记录边界**，原文永久保留可追溯。删轮刻意违反这条：用户的意图就是
「这段内容不要再进上下文，也不要再占地方」，落边界（正文仍在库）既瞒不过
意图也省不了空间。代价是**不可撤销**，所以入口放在确认框之后。
（若要「可撤销」，正确做法是先手工导出一份快照再删。）

## 后果与风险

- **前缀缓存**：删中间轮次后，后续请求的 prompt 前缀必然改变，缓存失效
  一次缓存重建——这是用户显式操作的预期代价。
- **不可撤销**：误删只能靠删除前的导出文件恢复。确认框文案已明示。
- **与压缩/回退的交互被拒绝**：含边界条目的轮次删不了，错误信息指路
  「请改用回退或重新压缩」。

## 否决的替代方案

- **只删单条消息**：留下 user 无 assistant（或反之），回放结构与展示都乱，
  且用户实际诉求就是「这一问一答都别要了」。否决。
- **软删除（标记隐藏）**：上下文长度一点没省，与「清理上下文」的目标相反。
  否决。
- **删除整段区间（多轮）**：需要多选交互，收益有限；单轮删除已覆盖绝大多数
  清理场景。将来若要批量，扩成 seq 数组即可，接口形状不变。
