# ADR-0030: 日记 tab 按目录存在性显隐——diary/ 是启用的唯一事实源

无日记需求的知识库也恒显日记 tab（`tab-bar`/`activity-bar` 硬编码），点进去是空视图——功能对不用它的人是噪音。决议：**知识库根目录存在 `diary/`（`DIARY_DIRNAME` 常量）即启用日记 tab，否则隐藏**。目录存在性由此成为日记功能启用状态的唯一事实源，五项配套决策如下。

## 决策

**D1｜判定时机——启动一次，刷新生效**：`/api/status` 新增 `diary_enabled`（后端 `stat` 一次），前端启动读取后确定导航，session 内不变。运行中建/删目录不实时响应（建目录是一生一次的动作，实时链路不值；未来可用 watcher 事件演进，本设计不堵路）。

**D2｜判定语义——空目录也算**：`stat` 到目录即启用，哪怕空。tab 是日记功能的**入口**而非已有日记的阅读列表——入口必须先于内容存在，否则「建目录 → 无 tab → 无处写第一篇」死锁。

**D3｜隐藏后兜底**：`#/diary` 直达、会话恢复的 diary 视图，统一在 router 守卫层重定向到 **files**（「看看目录里有什么」的语义）；两处导航（移动端 tab-bar / 桌面端 activity-bar）从 store 读同一 `diary_enabled`；会话记忆（diary.tab / reviewDate）保留不清（无害，目录回来即复用）。status 迟到窗口（`diary_enabled` 未知）按启用放行，status 到达且为 false 时补偿纠正。

**D4｜目录诞生权——API 永不创建 diary/**：无目录时**写端点**（录片段 / 上传照片 / 城市 / 编辑 / 删除）一律 409 `DIARY_NOT_ENABLED`，读端点自然空态。否则隐藏期间任何一次 API 写入（curl / PWA 缓存页 / 前端 bug）都会经 `_write` 的 `mkdir(parents=True)` 悄悄造出目录，刷新后 tab 凭空出现——「mkdir = 用户意图」被 API 副作用伪造，事实源失效。

**D5｜启用姿势——纯手工**：用户在知识库根目录 `mkdir diary`。不做设置页启用按钮、不做 API 化 mkdir——「启用」保持为纯文件系统动作，可发现性由本 ADR 与 README 承担。不做「停用」按钮（停用 = 删目录，目录里有用户数据，该按钮不该存在）。

## Considered Options

- 运行时动态显隐（watcher 推送）：否——低频操作不值实时链路，tab 使用中途凭空出现/消失是 UX 抖动（D1）。
- 要求目录内有 `.md` 才显示：否——首篇录入死锁（D2）。
- 写入即启用（维持 `_write` 自动 mkdir）：否——与显隐事实源正面冲突，事实源不可被写操作伪造（D4）。
- 设置页「启用日记」按钮（点击 = API mkdir）：否——保持手工动作的纯粹性；文档约定足够（D5）。
- 路由兜底落到 search：否——用户选 files（落点语义「让你看看目录里有什么」，与 D5 的手工建目录动线衔接）。

## Consequences

- 运行中 `mkdir diary` / `rmdir diary` 需刷新页面才反映到导航（D1 的既定代价）。
- `diary.py` 的 `_write`/图片落盘仍带 `mkdir(parents=True)`——写端点闸门（D4）保证它们只在「目录已存在」前提下触达子路径创建；主闸在 API 层，域层保留宽容实现（避免改动波及 diary_worker 等内部调用方）。
- 无目录时读端点返回空态而非 404：与「入口先于内容」一致，且不破坏 status 未返回前的前端放行窗口。
- `diary_enabled` 是布尔事实（无三态配置）：不引入 `CORTEX_DIARY_ENABLED` 之类的开关 env——目录存在性即配置，双事实源必然漂移。
