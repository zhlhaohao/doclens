# ADR-0003: PST 预览增强 —— 分页邮件列表 + 附件落盘下载 + HTML 正文转写

- 日期：2026-07-29
- 状态：已接受（经 grill-with-docs 会议逐项确认）
- 修订：ADR-0002 第 5 节「附件不持久落盘」自本 ADR 起作废

## 背景

ADR-0002 上线 PST 解析索引后，预览侧只有两个简陋入口：物理 PST 合成静态
md 目录页（前 200 个主题纯文本，不可点击、不可分页）、单邮件合成纯文本 md
（HTML 正文被拍平、附件只记文件名）。用户提出四项增强：列表分页、点击条目
预览邮件、附件可下载、HTML 邮件保持排版。

## 决策

### 1. 邮件列表：专用 JSON API + 前端分页表格（替代 md 目录页）

物理 PST 的预览从「合成 md 目录页」升级为专用分页表格：列 = 主题/发件人/
日期/文件夹，按日期倒序（无日期排尾），50 条/页，点击行进入该邮件的预览。
为此索引时把发件人/日期/文件夹随邮件文档一并入库（此前只有主题可查），
列表 API 直接分页查询，不再扫 structure_json。

### 2. 附件下载：索引时全量落盘（推翻 ADR-0002 §5）

所有 ≤100MB 的附件（不再限于白名单类型）在索引时持久化到数据目录
（`pst_attachments/<entry_id>/<文件名>`），预览页附件列表逐项可下载。
白名单附件的解析并入正文逻辑不变（ADR-0002 §5 其余部分仍然有效）。
否决「按需重解 PST」：大 PST 每次下载数秒延迟，且需为 Go sidecar 新增
单邮件定位模式，复杂度与失败面不成比例。

### 3. HTML 正文：索引时转 Markdown 存入节点文本（非 iframe 方案）

`body_html` 存在时优先转写为 Markdown 作为邮件文档正文（保持标题/列表/
表格结构）；无 HTML 时退回纯文本正文。搜索语料与预览同源。
否决「存 body_html + 沙箱 iframe 渲染」：虽然排版保真度更高，但引入第二条
存储通道、DB 体积上涨且搜索语料与预览分离；用户选择转写路线。
CID 内嵌图本期剥除（转写时丢 `<img>` 留 alt 占位）：cid→附件映射重写
保真度高但复杂，且 go-pst 对 content-id 的暴露未验证，后续可单独立项。

### 4. 旧索引迁移：指纹版本号自动重建

索引格式变化（正文转写、元数据入库、附件落盘）通过 `index_meta` 指纹
版本号升级表达，增量索引自动重建 PST 全部派生文档，无需手动 `--force`。

## 后果

- 磁盘：附件落盘对 2.4GB 样本 PST 估计多占 1~2GB（附件字节是 PST 体积
  大头）。>100MB 附件仍只记文件名，不可下载。
- 索引时间：PST 全量重建一次（分钟级，与 ADR-0002 §3 的同步模式一致）。
- 单邮件预览页从纯 md 升级为「邮件查看器」：头部 + 转写正文 + 附件下载
  列表 + 附件解析文本章节。
