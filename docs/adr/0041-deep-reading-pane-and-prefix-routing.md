# ADR-0041: 深读面板与前缀约定路由——书籍技能从用户调用面全隐

deep-read 技能生成的书籍技能（每本 ~600–1500 tokens 的 description）若走普通技能通道，会随技能清单进入每轮 system prompt（书多时线性膨胀）、并散布在斜杠候选/对话菜单/设置页/工具箱四个用户调用面。决议：**`_bookskill_` 前缀即身份（无状态、零配置、对未来生成的书自动生效）**，带该前缀的技能从四个用户调用面全隐、不进 system prompt 清单（模型感知面也隔断——普通对话中 AI 不知道有哪些书），唯一用户入口是 files 中栏的「深读面板」模式（同「未提交改动」视图形态）：列书（去前缀名+摘要，生成时间倒序）→ 点击跳 chat 新建技能会话直发开场白 → 行内删除钮真删。

## 决策

**D1｜前缀路由而非配置字段**：`user-invocable: false` 方案被否决——工具箱点击后发送的是斜杠形态消息，而斜杠注入权威（`_chat_slash.legal_slash_skill`）有 user-invocable 硬门，「工具箱可见 + model-only」根本走不通（列表看得见、点了不注入）；独立 frontmatter 字段需改 planify skill_loader（框架层加宿主专属字段，违反「引擎/框架代码中性化」红线）。前缀约定在 doclens 宿主层收口全部过滤口径，planify 零改动。

**D2｜全隐 = 可见面隐藏，不封底层通道**：斜杠注入权威对 `_bookskill_` 前缀**放行**（面板点书跳 chat 走现有 pendingSkillChat 斜杠链路复用）。「从用户调用面全隐」落地为各可见面按前缀过滤：斜杠引导候选 / 对话页技能菜单与最近技能 / 设置页技能管理（manage 端点）/ 技能工具箱白名单四处。

**D3｜不进 system prompt 清单**：与「停用 = 仅路由层隔断，load_skill 不受影响」的现有哲学显式分叉——书技能连模型感知面也隔断（普通对话提书名时 AI 不会联想路由到书技能）。这是对「每轮常驻 tokens 随书数线性膨胀」的取舍：书的价值在面板直达，不在对话联想。

**D4｜CJK 技能名放行**：slug 规则允许中文（`_bookskill_麦当劳准则`），但斜杠匹配正则与 API 名称校验都是 ASCII-only——扩字符集对 CJK 开放（面板/斜杠链路的前提，同时修复存量缺陷：中文名技能此前本来就匹配不上）。

**D5｜面板纯阅读入口**：无生成/停用/启用入口（生成走 `/deep-read` 普通技能；深读技能从设置页不可达 → 停用后无恢复入口，故不设停用语义）；删除 = 确认后真删（非内置技能，走 DELETE 端点真删分支）；入口按钮「有深读技能才显示」（进 files 页探测，同 gitChangesAvailable 先例）；数据源 = 专用端点 `GET /api/skills/books`（前缀过滤+排序+摘要一次返回，隐藏规则后端单一收口）。

## Considered Options

- 新开「书籍」tab：否——实际问答/生成工作发生在 chat tab，两个 tab 间跳转造成导航割裂（用户否决）。
- 复用 user-invocable:false + 面板开例外：否——见 D1 硬门冲突。
- 书技能聚合单行进 system prompt：否——用户明确选择完全不进清单（省 token 优先于对话联想）。
- slug 强转 ASCII（音译）：否——违背「原样保留不翻译」既定命名决策，音译有损。
- 存量书技能（无前缀如 mcdonalds-way）迁移：否——前缀规则自动适用于未来，旧技能自然保持普通技能身份。

## Consequences

- 生成器 deep-read 保持普通可见技能（斜杠可调），「全隐」只针对生成物。
- 深读技能在普通对话中不可被 AI 主动路由（提书名不会触发 load_skill）——用户须从面板进入；接受此可发现性代价。
- 四个隐藏面 + 面板端点 + 斜杠放行的过滤口径分散在多处（skills.py / _chat_slash.py / chat-view / files-view / skills-section），前缀常量须单一真相源，防止口径漂移。
- CJK 字符集扩展是全局放行（不只书技能）——任何中文命名技能此后可斜杠调用，属顺带修复而非风险。
