# ADR-0062: 数字员工——独立实体与「只评产物」的自驱评审循环

- 状态：已接受
- 日期：2026-11-25
- 关联决议：ADR-0011（模型预设——员工只存预设引用）、ADR-0026（压缩即事实——派活状态同为 append-only 条目）、ADR-0028（断开续跑——派活在后台跑完）、ADR-0043（工作目录热切换——在途派活不中断）、ADR-0061（兜底切换——工作回合受保护、评审不受）

## 背景

用户要一种「给一句话、自己干到达标」的自动化工作单元：有名字、专属提示词、工具与技能授权、模型、产物路径与模板、评审模型与评审提示词。它必须在一个独立会话里工作，干完一轮后由评审模型对产物打分，评审意见作为用户消息续聊，直到分数达到阈值。

它与团队 DAG 里的「角色」（随发行版分发的权限包）、遗留的「队友」都不同：角色是被派活的工人，没有「做到什么算完」的概念；数字员工自带产物契约与评审策略，是自驱的闭环。本仓库（基于 doclens 1.2.124）没有角色库，数字员工按独立实体设计，不引用、不扩展角色。

## 决策

### 1. 独立实体，机器级资产

数字员工配置存全局配置目录下的 JSON（与模型预设、MCP 配置同位），不参与知识库 Git 同步——员工引用的模型预设是机器级的，若员工跟着知识库走，换机后全部「预设缺失」。出厂为空，不预置示例。

### 2. 评审只看产物目录

员工的「产物路径」是目录前缀，每次派活在其下新建一个与该派活一一对应的产物目录。评审的唯一输入是这个目录的文本化清单；**不评对话回答**。

理由：「搜索最新的 agent 技术」这类任务若无文件产物，评审要么无据可依、要么要维护「评文件 / 评回答」两套口径。统一要求落盘后评审口径单一，且成果不随会话沉没。目录为空是「无产物」——评审前的确定性预检直接合成返工指令，不调评审模型。

### 3. 迭代 = 一个工作回合 + 一次评审

回合（一条用户消息 → 员工完整回复含全部工具调用）结束后才评审。回合中途不评：半成品评分无意义，且评审意见在回合内插不进去。评审意见以**返工指令**（用户消息形态、带标签与分数）落库并送入下一回合——复用全部既有会话机制（回放、压缩、回退）而零改动。

### 4. 评审是独立调用：无工具、无记忆、不走兜底

评审模型只凭评审材料 + 评审标准 + 原始任务打分，输出 0–100 单总分，**单次定胜负**（不做取平均、不做连续达标）。评审提示词只写**标准**，输出格式由系统骨架固定——使阈值在所有员工之间可比。评审**不走兜底切换**：换评审模型即换分数口径；评审调用失败（重试一次后）按「评审失败」结局终止，不当 0 分续跑、不当达标放行。

### 5. 结局封闭为五种

达标（分数 ≥ 阈值，默认 90）/ 轮数耗尽（最大迭代数，默认 5）/ 评审失败 / 用户停止 / 已中断（进程重启后不恢复——被中断的回合可能写到一半，重启即自动发起模型调用超出用户预期）。**否决**停滞检测：靠轮数耗尽兜底，简单优先。派活结束后会话归还为普通会话，不再自动评审，**不提供「继续迭代」**。

### 6. 状态由会话条目推导

派活开始、每次评审、派活结束各落一条专用条目；状态 = 有结束条目即已结束，否则进行中。不建独立的派活状态表（须与会话保持一致、导出导入不带它）。与压缩边界、回退边界同一 append-only 哲学。

## 后果

- 写入边界 = 仅产物目录：对结构化文件工具是硬保证，对 shell 与 MCP 工具只是纵深防御（后者在独立进程写文件，不经工具层），授权界面须明示——见 ADR-0063 的工具授权部分。
- 派活进行中禁发消息（与「生成中 409」同律）：循环中「下一条是谁在说话」必须确定。
- 派活开始时快照员工配置：中途改评审标准会使前后分数不可比。
- 产物目录固定为「当前版本」，不做逐轮归档：每轮分数与意见由评审卡留档，文件历史若知识库为 git 仓库则由 Git 同步自然保留。
- 实现需要把 `api/chat.py` 的「跑一轮 + 轮末落库」抽成公共协程——目前只有 SSE 路径能触发一轮，派活在后台运行需要离线入口。
