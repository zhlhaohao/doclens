# Git 同步的合并冲突自动解决 = 偏向本地（ours-wins）

知识库 Git 同步（auto-commit → pull → merge → push）在遇到合并冲突时自动偏向本地：本机内容胜出，远端机器的改动从工作区静默消失（git 历史中仍可捞回）。

这一决策是在明确展示过风险场景后做出的：两台机器都在 auto-commit 的纯自动环境下，"本地"只是"这台机器的机器人提交"，偏向任何一边都等于随机丢一边；union 合并（双边保留）能做到零数据丢失、最坏结果只是段落重复。用户仍选择偏向本地。

## Considered Options

- **union 合并（文本双边保留 + 二进制留 .conflict 副本）**：零数据丢失，但会在文件中留下重复段落需要手工清理——被否决。
- **偏向远端（-X theirs）**：本机未推送改动被静默覆盖——被否决。
- **偏向本地（-X ours）**：采纳。

## Consequences

- 冲突时另一台机器的改动从工作区不可见，只能由懂 git 的人从历史中捞回；产品上不提供任何"冲突已发生/内容已丢失"的显式提示（仅有通用的同步弱提醒机制）。
- 未来若要改为 union，只需替换 merge 策略实现，决策本身可逆；但已发生过的"静默丢失"无法追溯补偿。
