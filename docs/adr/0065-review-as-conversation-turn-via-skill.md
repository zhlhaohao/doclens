# ADR-0065: 评审回合化与技能化——评审在同一会话里由员工按评审技能完成

- 状态：已接受
- 日期：2026-11-26
- 关联决议：ADR-0062（§4「评审是独立调用」**被本决议取代**）、ADR-0063（§1「技能预加载」**被本决议取代**）、ADR-0064（精简基础提示词——技能段**恢复**）

## 背景

ADR-0062 把评审实现为宿主另起的一次独立模型调用：宿主把产物目录文本化后喂给评审模型，模型无工具、无记忆，返回分数。实施后用户指出它不够灵活——评审方法被硬编码在宿主里（看什么、怎么截断、怎么算分都是固定的），而真实评审往往需要：用 Office 工具解析 docx、用浏览器打开网站测加载时间、跑脚本做确定性检查、按任务性质定制的检查步骤。这些都应该由**技能**承载，而不是改宿主代码。

同时暴露了旧设计的三个隐含假设，均被推翻：产物一定是文件（可以是代码改动或部署在外的网站）、评审不应有工具（评审要记笔记、跑脚本）、技能应预加载（评审技能预加载会让员工在工作回合就看到评审方法）。

## 决策

### 1. 评审是同一会话里的一个回合，不是独立调用

工作回合结束 → 宿主代发**评审指令**（用户消息形态）→ **员工自己**加载评审技能、用工具找产物/核实/跑脚本 → 调用 `submit_review` 提交结果。评审员不是独立代理：与工作回合同一个模型实例、同一份工具表、同一份对话历史。评审回合计入会话历史，但不计入「迭代」的工作部分（一个迭代 = 工作回合 + 评审回合）。

**否决**独立评审代理（评审员）：多一个实体、多一套工具授权，且评审看不到员工的工作过程。

### 2. 评审技能 = 普通 SKILL.md，与工作技能同构

评审技能只写**方法**（找什么、用什么工具、什么步骤、怎么打分）；员工的**评审标准**写**要求**（这份产物的具体要求）。两者并存：技能可跨员工复用，标准随评审指令一并给出。输出格式不靠文本约束——由 `submit_review` 工具的 schema 固定。

**否决**把标准写进技能（不可复用）、宿主调用技能目录内的可执行入口（技能就是技能，不是程序契约）。

### 3. `submit_review` 是评审回合的结束契约

模型调用它即评审结束（宿主拿到入参后回合终止）；**回合结束却未调用 = 评审失败**，派活终止。否决「催一次再给机会」与「从文字里解析分数」。达标判定只看分数，`passed` 字段仅作参考。

### 4. 技能全部按需加载，员工持有受白名单约束的 `load_skill`

推翻 ADR-0063 的预加载：技能清单进系统提示词，员工在需要时加载。`load_skill` 由宿主包装——只允许白名单（工作技能 ∪ 评审技能）内的名字。派活说明点名应加载的工作技能；评审指令点名评审技能。派活说明不再预检任务文本里点名的技能（自然语言形态太多，预检不可靠），靠 handler 拒绝 + 员工如实汇报。

### 5. 内部技能：与公开技能物理隔离

数字员工的工作技能与评审技能都是**内部技能**——存放在独立的内部技能库（机器级，与员工库同位），**不在 skills 目录**，从全部用户调用面（技能配置页、斜杠命令、对话技能菜单、工具箱）不可达，唯一触达方式是数字员工。由独立的技能加载器实例扫描，与公开技能的加载器互不可见。出厂为空、不内置通用评审方法（评审要按任务性质设计）；本期无管理 UI，用户直接放目录。**引用的内部技能不存在 → 派活失败**（配置悬空即失败，不静默降级）。

**否决** `_bookskill_` 式前缀隐藏（仍是公开技能、斜杠可注入）、放进 skills 目录再加过滤（物理隔离才可靠）。

### 6. 评审模型是有序可选清单

评审回合按清单顺序尝试模型预设，首个不可用（额度耗尽）顺延；**清单为空 = 用工作模型评审**。评审回合的兜底范围 = 评审清单本身，不借用全局兜底清单（那是工作模型的口径）。

### 7. 评审回合可写、不限制工具

评审与工作回合同一工具表，**不禁写**——评审要记笔记、跑脚本生成测量结果。靠评审指令约束「不要修改被评审的交付物」。评审产物放哪、如何与交付物区分，不做约定，由评审技能自己分辨。

**否决**评审回合只读（削弱评审能力）、mtime 检测强制返工。

### 8. 删除宿主侧的评审材料整理与无产物预检

宿主不再把产物目录文本化、不再做预算截断（员工自己用工具读，大文件由工具自身的截断与评审技能的方法处理）；不再做「目录是否为空」的预检——产物可能是代码改动或部署在外的网站，目录为空不代表没产物。

### 9. 消耗预算：派活级的 token 硬上限

评审回合有工具循环，一个回合也能烧很多 token；仅按迭代数设限不够。新增员工配置 **token_budget**（默认 200 万 / 派活；0 = 不限）：计量 = 派活会话内全部 LLM 调用的 `input + cache_read + cache_creation + output`（四字段全算不加权）。每次回合结束后检查，**超出即终止**，结局「预算耗尽」；正在进行的那一回合跑完（不在回合中途硬杀）。80% 时在返工指令前缀预警。另设员工级单回合工具调用上限（默认 40），防一个回合内死循环。

## 后果

- 员工配置变化：`review_model_preset_id` → `review_model_presets`（有序清单）；新增 `review_skill`（必填）、`token_budget`、`max_tool_rounds`；`skills_allow` 语义改为内部技能白名单（按需加载）。
- `FORBIDDEN_TOOLS` 移除 `load_skill`。
- 精简基础提示词（ADR-0064）恢复技能清单注入与加载引导。
- 评审卡新增 `checks`（评审技能的逐项检查明细）；评审指令与返工指令折叠卡内。
- 评审回合的 assistant 消息与工具调用照常显示——用户要能看到评审是怎么得出的。
- 同一模型评自己的产物严格度打折：靠评审技能的评分规则（分档扣分、用工具核实）弥补，这是技能作者的责任。
