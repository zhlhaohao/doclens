# ADR-0050：slides-gen —— 产物由 PPTX 改为 HTML，并内置逐页视觉验收

日期：2026-10-29
状态：已接受（取代 ADR-0049 的产物形态与验收方式）

## 背景

ADR-0049 落地的 pptx-gen（md → PPTX）经真机试用暴露两类根本问题：

1. **没有视觉反馈闭环**：LLM 只写 MD、转换器只做坐标映射，谁都没"看见"成品。文本框重叠、内容溢出、配色失衡只能靠人肉发现，返工成本高。
2. **PPTX 不是 LLM 该操作的介质**：PPTX 的版面是绝对坐标 + 独立文本框，LLM 既要算布局又要管视觉，能力错配。实测 `renderer.py` 的 `_stack_offset` 在同一 slot 内叠放多个块时直接算出重叠矩形（`idx=0` 返回原矩形占满整区），这是坐标系方案的固有脆弱性。

## 决策

1. **产物改为单文件自包含 HTML**，不再产出 PPTX。
   - CSS 流式布局天然免疫文本框重叠；一份 HTML 双击即看、可直接转发、可打印导出 PDF。
   - 样式/脚本内联，图片默认 base64 内嵌 —— 单文件可离线分发。
2. **支持点击翻页与动画**（用户明确要求）。零依赖 presenter.js：
   - 导航：`← →` / 空格 / PgUp / PgDn / Home / End / 点击 / 滚轮 / 触摸滑动
   - 功能：`N` 备注、`F` 全屏、`P` 打印导出 PDF、`H` 隐藏提示
   - 动画：白名单词（`enter.fly-in|fade|zoom|wipe`、`exit.*`、`emphasize.*`）→ CSS keyframes；页级策略 `bullets:` / `all:`；`trigger=click` 支持逐项点击
3. **每页必须通过视觉验收**（用户要求"一直修到全部通过"）：
   - `renderer/qa.py` 双层检查：
     - **geom（确定性）**：元素重叠、内容裁切、越出安全边距、最小字号（<16px 即 high）、信息密度、图片变形
     - **vision（语义）**：playwright 2x 截图 → 视觉模型按 8 项审美清单打分 + 输出结构化 issues
   - 判定口径统一为 **「无 high 问题 且 score ≥ 70」**；不采信模型自报的 `pass` 字段（实测与 score 自相矛盾，会导致循环不收敛）
   - 产物：`<name>-qa/pXX.png`（截图）、`report.md`（人读）、`report.json`（机读）
   - `build` 命令退出码 0/1 即「是否全部通过」，供 agent 判定修复循环何时结束
4. **内容自适应不靠缩字号硬塞**：
   - autofit 二分求 `--fit` 字号倍数，**下限由可读性反推**（页内最小字号不得 <17px）
   - 缩到底仍溢出 → 打 `data-fit-overflow` → 几何检查报 `high/overloaded`「必须拆页」
   - 这是「发现问题 → 定位到内容层 → 拆分/精简」的强制通路，而非把字压到 11.9px 糊过去
5. **技能更名 `slides-gen`**，pptx-gen 全部删除（仓库/全局/site-packages 三处）。中间格式 MD 与 SCHEMA 保留并改写（ptx 语义换 HTML 语义）。

## 后果

- 优点：LLM 只需产出 MD（认知负担最小）+ 读问题清单迭代；视觉质量由闭环保证而非祈祷；产物可离线分发、可打印成 PDF。
- 代价：
  - 验收依赖视觉模型 API（未配置时降级为纯几何检查，审美问题不覆盖）。
  - 每页一次视觉调用，11 页 deck 约 2-4 分钟（视觉模型串行）。
  - 视觉评分有抖动：同页两次可能 72 / 86，故只把 `high` 与 `score<70` 当阻断项，medium/low 记为建议。
- 已知边界：
  - 导出真 PPTX 的能力不再提供（用户已确认不要）。
  - 打印分页在 Chrome/Edge 最稳；复杂效果（backdrop-filter 等）打印可能丢失。
  - blank 版式为坐标逃生舱，坐标越界由作者负责（几何检查对其豁免安全边距）。
