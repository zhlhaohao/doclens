# ADR-0061: 额度耗尽时的回合内兜底模型切换

- 状态：已接受
- 日期：2026-11-25
- 关联决议：ADR-0011（模型预设——兜底清单只存预设引用）、ADR-0034（视觉路由能力位——带图回合的候选资格）、ADR-0053（框架宿主注入——兜底解析器的分层依据）

## 背景

对话回合进行中（尤其是长工具链）主模型套餐额度耗尽——GLM 5h/周上限、MiniMax 用量超限、Kimi `exceeded_current_quota_error`——旧实现有两种结局都不好：

1. GLM 把 5h/周上限 `1308/1310/1316-1321` 放在「可重试」业务码表里，runner 退避重试 4 次（≈45s）后整轮报废；
2. 其它家的额度错误归「不可重试」，一次失败即整轮报废。

长任务几十轮工具调用的成果全部丢失，用户只能手动换模型重发。用户诉求：预先设定多个兜底模型，额度耗尽时按优先次序自动切换、保证对话继续，并明确告知用户。

## 决策

### 1. 「额度耗尽」独立分类，移出重试表

`upstream_errors.py` 新增「额度耗尽」判定；GLM `1308/1310/1316-1321` 从 `_GLM_RETRYABLE` 移出。切换触发 = 额度耗尽 **或** 瞬时错误（限流/网络/5xx）重试耗尽。配置类错误（鉴权/模型不存在/参数/内容审查）**不触发**——静默换模型会把配置问题藏起来。

### 2. 作用域 = 单回合，不动全局配置

切换只换本回合 StreamingAgent 的 provider/model，**不写回激活预设、不改 .env**。回合内只向下不切回；下一回合从主模型重新开始（多付一次被拒调用，换「设置即真相」的简单语义）。**否决**跨回合的「已耗尽」记忆——不同供应商窗口时长不同，TTL 状态机带来的复杂度高于它省下的几秒。

### 3. 候选排序：同源提权

与主模型同供应商（按 base_url 识别，沿套餐额度口径）的兜底排到最前；同供应商内，`model_id` 大小写不敏感精确相等者再排前（= 换账号续跑同一模型）；其余按清单原序。

### 4. 预检三级口径：并行预检、串行试调

- 能拿到窗口百分比的：**只看 5 小时窗口**——已用 ≥ 窗口阈值（默认 80%）即不可用；周窗口不参与（2026-11-25 修订：实测 GLM 三个账号周窗口 97% 但 5h 仅 48%，按周剔除会把同源候选全部刷掉直接跳到别家）；
- 能拿到余额的：余额 < 余额阈值（默认 10）即不可用；
- 都拿不到 / 预检出错：退回**试调**（以正式调用为探针，被拒额度耗尽即换下一个）。

预检**并行**（总耗时 = 最慢的一个），试调**串行**（不能同时向多个模型发正式请求）。每候选每回合至多试一次。**否决**「预检失败 = 候选不可用」——额度接口挂了 ≠ 模型不可用。

### 5. 中途切换

本次调用已流出部分内容才失败：仍切换，先注入 user 角色 `<model-switch>` 系统提示（上一条中断、请从头重答），本次调用中**未完成**的工具调用丢弃。

### 6. 分层：框架出机制、宿主出策略

- planify：额度耗尽判定；`StreamingAgent(fallback_resolver=...)` 钩子——runner 在切换触发点问 resolver「下一个 provider+model」，自己负责消息修补、执行切换、发通知。不读宿主预设/额度/`CORTEX_*`。
- doclens：resolver 实现（清单 + 同源提权 + 并行预检 + 构造候选 provider）、SSE 事件、时间线落库、设置页。

**否决**「宿主外层捕获错误重建 agent 重跑」——回合内状态（messages、工具链）在 runner 手里，外层拿不到，且重跑会重复工具调用。

### 7. 告知三层

切换时 toast；切换记录进思考过程时间线并随回合落库（`model_switch` 合成条目）；全部候选耗尽时错误文案列出各候选被拒原因；未配清单时引导去设置页。切换期间时间线显示进行中状态。

## 明确不做（本期）

- **子代理 / teammate 不受保护**：它们持有共享主模型实例，主循环切换后仍找主模型。已知缺口，留二期。
- **工具调用能力不预检**：无法可靠判断，由用户保证清单里的模型支持工具（设置页说明文字提示）。
- **跨回合失败记忆**：见 §2。

## 后果

- 主模型耗尽后回合不丢，代价 = 并行预检（≤15s）+ 逐个试调的等待；时间线有进行中状态。
- 「切换」只是救场：设置页仍显示主模型为激活预设；用户切回/充值后下一回合自动回归主模型。
- 架构守卫（`tests/test_architecture.py`）需同步：`fallback_resolver` 是公共钩子，planify 侧不得出现宿主名与宿主配置。
