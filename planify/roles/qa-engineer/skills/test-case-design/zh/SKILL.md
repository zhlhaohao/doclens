# 测试用例设计

功能：{功能}
依据：{需求或验收标准}

## 步骤
1. 列出这个功能的输入、输出、状态和依赖（网络、文件、其他服务）。
2. 每条验收标准至少对应一条用例。
3. 用下面的维度补全用例，不适用的维度写一句为什么跳过：
   - **正常路径**：最常见的用法
   - **边界值**：最小、最大、刚好越界、空、单个、很多
   - **异常输入**：格式错误、类型错误、特殊字符、超长、重复提交
   - **状态**：未登录、权限不足、数据不存在、数据已被别人改过
   - **中断与恢复**：网络断开、超时、取消、应用重启
   - **并发**：同时操作同一数据
   - **兼容**：不同系统（macOS / Windows / Linux）、浏览器、屏幕、语言
   - **回归**：这次改动可能影响到的相邻功能
4. 按风险排优先级：P0（必须测，阻塞发布）、P1（应该测）、P2（有空再测）。
5. 能自动化的用例标出来，并说明放在哪个测试文件里。

## 使用边界

优先使用已有信息；用户的数量、格式和任务范围优先于本文默认模板。工具权限、主目录/附加只读、Plan 模式与预算以当次实际能力为准；不换工具规避拒绝。这里只给工作方法，不授权写入、命令、付费、发送、提交或发布；未执行/验证的步骤如实标明。
