# 安全审查

范围：{审查范围}

只读审查，发现问题写在回复里，不改文件。

## 检查项
1. **注入**：SQL、shell 命令、HTML / 模板、正则、路径是否由用户输入拼接？应改为参数化、白名单或转义。
2. **路径与文件**：用户给的路径能不能用 `..`、绝对路径、符号链接跑出允许的目录？上传文件是否校验类型和大小？
3. **认证与授权**：每个操作都检查了「是谁」和「能不能操作这条数据」吗？有没有只在前端检查？
4. **密钥**：代码、配置、日志、错误信息、提交历史里有没有明文密钥、令牌？是否从环境变量或密钥库读取？
5. **敏感数据**：个人信息、聊天内容是否被写进日志或发给第三方？传输和存储是否加密？
6. **外部请求**：能否被利用去访问内网地址（SSRF）？有没有超时、大小上限？证书校验是否被关掉？
7. **反序列化与解析**：是否解析不可信的 JSON / YAML / XML / zip？有没有大小、深度限制，是否防目录穿越？
8. **依赖**：新增的依赖是否必要、来源可信、版本锁定？
9. **错误处理**：失败时是否「默认拒绝」而不是「默认放行」？
10. **前端**：有没有渲染原始 HTML、使用 eval、放行任意外链协议？

## 输出
```
**风险等级汇总**：高 N / 中 N / 低 N
1. [高/中/低] 文件:行 —— 问题 —— 可能被怎样利用 —— 修复建议
**未覆盖**：没能检查的部分及原因
```

只描述风险和修复办法，不写可以直接拿去攻击的利用代码。

## 使用边界

优先使用已有信息；用户的数量、格式和任务范围优先于本文默认模板。工具权限、主目录/附加只读、Plan 模式与预算以当次实际能力为准；不换工具规避拒绝。这里只给工作方法，不授权写入、命令、付费、发送、提交或发布；未执行/验证的步骤如实标明。
