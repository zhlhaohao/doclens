# README 再生成（gen-readme）

为**当前工作目录中项目**（或用户指定的模块目录）重新生成 README。任意技术栈，零项目假设。README 是**构建产物**：每次调用全量重生成、整文件覆盖。

## 产物

| 范围 | 产物 |
|---|---|
| 整个项目（未指定对象） | 根 `README.md`（英文，GitHub 默认首页）+ `README.zh-CN.md`（中文），两份顶部互链、同步重生成 |
| 用户指定模块路径 | `<模块路径>/README.md`（语言同上双份规则） |

普通"讲讲这个项目"类提问不跑本技能——直接口头回答。

## 流程（四步）

### 第 1 步：定向收集事实（主代理直接做，不派子代理）

用 glob/grep/read_file 定向读（通常 <20 个文件）：

1. **旧 README**（如有，含各语言版本 `README*.md`）：全文通读——徽章、截图/GIF、联系方式、致谢、License 声明等**代码外资产**记录待吸收；
2. **工程定义文件**（技术栈与版本）：`pyproject.toml` / `package.json` / `go.mod` / `Cargo.toml` / `pom.xml` 等；
3. **入口与启动**：启动脚本、CLI 入口、Makefile/justfile、`start*.ps1|sh`、`Dockerfile` / `docker-compose*.yml`；
4. **配置**：`.env.example`、配置文件、`sql/` 或数据库迁移目录、默认端口、默认账号密码线索；
5. **目录树**：顶层结构（README 的目录结构章节用）；
6. **功能发现**：grep 路由/命令/页面/CLI 子命令定义处，汇总功能清单（以代码为准，不信旧 README 的功能列表）。

有则读、无则跳过，不假设存在。

**完成标准**：技术栈版本表、启动步骤素材、功能清单、目录树、旧 README 资产清单五项到位。

### 第 2 步：拟大纲（启发示例，不是清单约束——一切以「这个项目对读者最需要什么」为准，敢于超出示例增删）

前后端分离项目常见章节（适用才收）：
- 项目标题 + 一句话简介（做什么、解决什么问题）+ 徽章 + 截图/GIF；
- 功能特性（列表，区分核心/附加）；
- 技术栈（前端/后端/数据库/中间件/DevOps 分开写）；
- 前置条件（版本下限：Node/JDK/Python/DB 等）；
- **快速启动**（最核心章节：克隆→后端（导 SQL→改配置→启动）→前端（install→改代理→dev）→访问地址与默认账密；有 docker-compose 加一键启动）；
- 目录结构（代码块树）；
- 环境配置（开发/生产区分、BASE_URL、密钥不硬编码提醒）；
- 打包部署（build 命令、nginx/jar 运行、Docker、HTTPS）；
- License、联系方式/致谢（可选）。

快速启动章检查项（避坑）：SQL 脚本位置与导入顺序写明；默认账号密码单独标出不藏配置文件；区分开发/生产环境；后端/前端端口号写明防冲突。

库/CLI/工具型项目按其性质取舍（CLI 讲安装与命令示例，库讲 API 与最小用法）——示例没覆盖的重要维度（在线 Demo、FAQ、Roadmap、贡献指南……）发现了就加。

**完成标准**：章节大纲成形。

### 第 3 步：用户确认（一轮合并呈报）

同一轮呈报三样，等用户确认后才动笔：

1. 章节大纲（每章一句拟写内容）；
2. 旧 README 资产去留清单（徽章/截图/联系方式/致谢/协议自动保留进新稿——拿不准或疑似过时的列出让用户勾选）；
3. 代码发现的功能列表（用户可增删改）。

用户否决/点名时按其意见修改再确认一轮。

**完成标准**：三项均经用户确认。

### 第 4 步：写 README（中英双份同步生成）

覆盖写入两份文件（模块模式写在模块目录下）：

- `README.md`（英文）与 `README.zh-CN.md`（中文）**内容等价**，顶部互链（英文版顶部 `[简体中文](README.zh-CN.md)`，中文版反之）；
- 头部声明（两种语言各写一遍）：`> ⚠ 构建产物：本文件由 gen-readme 技能全量重生成（中英双份同步），手工内容请在确认环节声明保留。生成日期：<YYYY-MM-DD>`；
- 启动命令、配置项必须来自第 1 步实际收集的命令与文件路径，禁止编造；默认账密找不到就写"见配置文件"并注明位置，不虚构；
- License 以仓库实际存在的 LICENSE 文件为准；无则该节省略并提醒用户补充。

**完成标准**：双份写入、内容等价、互链有效、头部声明齐全。

### 收尾核验

- 自查：启动步骤按新稿走一遍能否跑通（命令存在、路径存在、顺序合理）；功能列表与代码一致；资产按确认清单吸收完毕。
- 向用户汇报：产物路径、从旧 README 吸收/丢弃了什么、发现的问题（如缺 LICENSE、SQL 无导入说明、密钥疑似硬编码）。

## 约束

- 本技能只写目标 README 两份文件，不触碰其他文件。
- 代码为唯一真相：功能、命令、版本、配置以代码与配置文件为准，与旧 README 冲突以代码为准（用户确认的资产除外）。
- README 面向人类读者写作：完整句子、命令带注释、步骤编号清晰——但这是**产物**的风格要求（本 SKILL.md 自身面向机器，措辞随意）。
