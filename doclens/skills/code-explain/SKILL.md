# 源码解读技能（code-explain）

对**工作目录中的源码文件**做即席解读——ephemeral 问答，不向磁盘写任何产物文件。用户给出文件名+起止行号（或对象名）并提出要求（如「帮我解读这个函数」「XX 变量是什么意思」），agent 定位对象、按对象类型的基线章节作答。

## 硬边界（先判定归属）

- **本技能只管**：工作目录中的源码文件（read_file / grep / glob 直接寻址），且用户点名了**具体代码对象**（文件+行号 / 文件+对象名 / 光秃对象名）并要求解读/讲解/分析/含义。
- **不归本技能**：
  - 「讲讲这个项目/某模块的架构」→ repo-wiki（或普通提问直接口头回答）；
  - 知识库文档（含 KB 内代码文件）的问答 → ask-files（词序号体系）；
  - 「这个 bug 怎么回事」类调试 → 普通诊断流程，不走本技能基线；
  - 跨文件的机制/概念（「讲讲缓存体系」）→ repo-wiki 分册 feature 轨——本技能只做**点得出位置**的对象。

## 第 1 步：定位对象（行号优先、名字兜底）

1. **有行号** → read_file 该区间，判定语法边界后再决定精读范围。行号是**锚点不是围栏**：仅用于定位，解读时允许外扩读上下文，回答聚焦所指对象。
   - 预览页工具箱来的路径可能带 `:区间` 后缀（行选择机制，如 `src/app.py:12-40,88-120`，多区间逗号分隔）——路径与区间拆开解读，每个区间一个对象。
   - 拆出的路径若不存在，先剥掉 `:区间` 后缀再试一次原路径（防把带后缀串当真实文件名）。
2. **无行号有对象名** → grep 定位定义处（`def name` / `class name` / `name =` 等按语言适配）：
   - 唯一命中 → 直接解读；
   - 多命中 → 列候选（文件:行号 + 签名首行）请用户挑，**不猜**；
   - 零命中 → 如实报告找不到，附最相近候选（拼写近似）；仍无则明确说找不到。
3. **语法边界智能对齐**：用户区间与语法单元不重合（切在函数中间、横跨两个函数）时，扩到完整函数/类边界解读，并**显式回报对齐结果**（「你给的 12-40 行实际是函数 `foo` 的 15-38 行，按函数解读」）。
4. 歧义宁可问：解读错对象是本技能最贵的失败。

## 第 2 步：判定档位（双档）

- **焦点问句**（「XX 是什么意思」「这个参数干嘛用的」——单一问题）→ 直答焦点，基线章节只取与焦点相关的节支撑，不做全量外扩（如变量含义问不 grep 全仓读写点）。
- **解读指令**（「解读/讲解/分析 + 对象」）→ 全套基线硬下限（见第 4 步）。
- **判不准从重**：按解读指令走全套，宁全勿缺。

## 第 3 步：读码（主代理直读，零子代理）

- 主代理自己 read_file + grep，**不派 task 子代理**。
- **巨型对象骨架先行**（对象 >~1000 行）：先 grep 扫 class/def/签名建骨架，只对用户锚点命中的部分精读。
- **外扩纪律**（防输入爆炸）：
  - 必查分级——焦点问句：定义处（+类型定义，如有）；解读指令（函数/类）：另加直接调用方（grep 名字，命中 ≤5 处各取 2-3 行上下文）与项目内被调子程序（读到签名+docstring 层即可）；
  - **递归深度 = 1**：子程序的子程序不追（用户点名除外）；
  - **第三方库不深入**：import 的外部依赖只按名字+调用形态推语义，不读库源码；
  - grep 命中处只取必要上下文行（-C 参数），**禁止为一个定义/调用点整文件重读**；
  - **读码预算**：单次解读总读码 ≤800 行（对象本体+外扩合计，多对象共享）；超了先砍外扩保对象本体，并在回答中如实声明「上下文外扩从略」——不静默降质。

## 第 4 步：按类型基线作答（硬下限）

每类一套基线章节，是**硬下限**：每节必答（确实无内容时明写「无/不适用」，不静默删节）；相邻节可合并、按对象性质可加节；禁止机械填充凑节。

**函数/方法**：①一句话职责 ②签名解读（参数/返回值/类型含义）③执行流程（控制流分步）④关键依赖（调谁/被谁调）⑤状态与副作用（读写状态、IO、落库）⑥异常与边界（抛错、边界条件、退化路径）

**类/接口/类型**：①一句话职责 ②核心状态（字段表）③对外接口（public 方法表）④协作关系（依赖/被依赖、继承实现）⑤生命周期（构造到销毁）⑥设计意图（为什么长这样，有线索才写）

**变量/字段/参数**：①一句话含义 ②类型与取值（值域/单位/格式）③生命周期（何时赋值、可变吗）④读写点（谁写、谁读、在哪）

**语句片段**（不构成完整函数的任意行区间）：①这段在做什么 ②逐块解读 ③上下文依赖（依赖外部的什么）

**整个文件**：①模块职责 ②结构导览（顶层定义清单表）③关键流程 ④对外接口（导出面）⑤依赖关系

**多对象请求**：逐对象独立成节，各自走各自类型的基线；读码预算整体共享；不做「A 与 B 对比」之类的自主发挥（用户明说「对比」除外）。

## 呈现规范

- **不整段复读代码**——用户编辑器里就开着这段代码；只在关键处引 1-3 行片段辅助定位。
- 引用一律带 `文件路径:行号`。
- 执行流程用**编号步骤**叙述；不强制 mermaid（ephemeral 回答优先轻量），确信图更清楚时可画。
- **人话文风**：完整句子讲机制；标识符用反引号做定位线索，一句话 ≤2 个裸标识符；术语首次出现给一句人话；杜绝电报体。
- **代码即真相**：解读以源码为唯一真相；与注释/文档冲突时以代码为准，并在回答中指出冲突。
