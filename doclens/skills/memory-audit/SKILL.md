# 人工审计记忆（memory-audit）

## 定位

把 `~/.cortex/memory/`（记忆库根，下称 `<memory>`）里的记忆条目逐条交给**用户本人**审核——AI 只做取出、呈现、按用户裁定执行，**不替用户判断**。审计是记忆协议的治理面：模型自律写入的内容，由人定期把关。

## 审计流程（严格循环，不可跳条）

对索引（`<memory>/MEMORY.md`）中**每一条指针**依序执行：

1. **取出**：read_file 打开该条目的笔记文件，通读全文。
2. **呈现**：向用户展示——条目 slug、类型（frontmatter `type`）、索引钩子行、笔记正文全文。一次只呈现一条。
3. **问裁定**：问用户四选一——
   - **通过**：内容准确、仍有效，保留不动；
   - **编辑**：用户口述修改（改事实、改措辞、改 Why/How），AI 执行后把改后全文再展示一次确认；
   - **补充**：内容对但缺料（如 feedback 缺 Why、信息过时），用户口述补充，AI 合入后同样回显确认；
   - **删除**：不再成立或从未该记——移入 `<memory>/archive/` 并摘除索引行（退役语义，文件保留）。
4. **执行**：按裁定落盘。编辑/补充要 bump 笔记 `updated:` 日期；删除要同步改 MEMORY.md。
5. **下一条**：循环直到索引指针全部过完。

## 硬约束

- **逐条问、逐条执行**：禁止把多条打包成一次提问（用户看不到全文就没法裁定）；禁止用户未裁定就批量处置。
- **顺序取条**：按索引分区顺序（user → feedback → project → reference），条目按出现顺序。用户可说「跳过」留待下轮，可说「到此为止」中止——中止时报告已审/未审各多少条。
- **AI 不预判**：呈现时不写「这条好像过时了」之类的引导性评语——裁定权在用户；用户问意见时才给，且明确标注是建议。
- **只审索引内条目**：`archive/` 里的是已退役文件，不进审计；孤儿笔记（在库但不在索引）审计结束时列出文件名报给用户，问是否补入索引或归档，不自动处理。
- **凭据检查**：呈现时若发现正文含疑似凭据值（密钥、密码、token），提醒用户记忆协议禁存凭据值，建议删除或改存位置。
- **收尾报告**：全部处理完后报告——通过 N / 编辑 N / 补充 N / 删除 N / 跳过 N，索引当前行数；本报告同时就是写后必报格式。

## 与记忆纪律的衔接

- 审计中的删除/编辑**不适用**「用户撤销的偏好不重新写入」——那是防误写回；审计是用户显式治理，其裁定就是最新意志。
- 审计本身不是记忆写入任务：不因「用户说通过」就 bump 时间戳；只对编辑/补充（实际改动）bump。
