# LLM Wiki 维护技能

Karpathy LLM Wiki 范式的本项目实现：**raw（知识库原文，只读）→ wiki/（LLM 编译的结构化 Markdown 页）**，知识在摄入时一次性加工沉淀，查询时优先用成品知识。

## 目录契约

```
<workdir>/
├── 各主题目录/          # raw 层：原始文档，LLM 只读不改
└── wiki/               # wiki 层：LLM 全权读写的目录
    ├── index.md        # 内容目录：每页一行「- [标题](相对链接) — 一句话摘要」，按分类分组
    ├── log.md          # 时间线日志：append-only，每条以 `## [YYYY-MM-DD] <op> | <主题>` 开头
    └── <主题>/         # 主题子目录，如 wiki/llm-wiki/
        └── <页面>.md   # 单主题页：概念页/实体页/对比页/综述页
```

**红线**：
- LLM **只写 `wiki/` 内文件**，绝不修改 wiki/ 之外的任何知识库文档。
- 首次使用若 `wiki/` 不存在：创建 `wiki/index.md`（含 `# Wiki 索引` 标题与「暂无页面」占位）和 `wiki/log.md`（含 `# Wiki 日志` 标题），记一条 init 日志。

## 页面格式（Schema）

每个 wiki 页：

```markdown
---
title: 页面标题
tags: [主题, 子主题]
sources: [原文档相对路径1, 原文档相对路径2]   # 本页编译自哪些 raw 文档
updated: 2026-10-11
---

# 页面标题

## 摘要          # 3~5 句核心结论
## 要点          # 分节展开，每节聚焦一个子主题
## 相关页面       # wiki 内双向链接：[[wiki/主题/其他页.md]]
## 来源          # 编译来源的 raw 文档相对路径列表
```

约定：
- 一页一主题，标题即规范术语；同义词在摘要中注明。
- wiki 内互链用 `[[相对路径]]` 形式（Obsidian 兼容）。
- 新素材与已有页面矛盾时：**不删旧结论**，在页面中标注「⚠️ 与 X 冲突：<说明>」，由 lint 或用户裁决。
- **index.md 按 wiki 子目录分组**（如 `## doclens-arch`、`## ai-km`），与文件结构一致；新增主题目录即新增同名分组。不分组平铺在 10+ 页后难读。

## 操作一：Ingest（摄入）

触发：「摄入 X 到 wiki」「把这篇编译进 wiki」「ingest」。

流程（一次摄入可能触及 10~15 个 wiki 文件，全部用 write_file/edit_file 完成）：

1. **读源**：`file_info` → `read_document` 读目标文档（大文件按章节读全）。
2. **定位**：读 `wiki/index.md`，并**必须 `kb_grep`/`search_kb(paths=["wiki"])` 搜素材主题词**看已有哪些页——不靠记忆判互链对象（10 页后人脑必漏，搜一遍几秒零成本）。必要时 `search_kb(paths=["wiki"])` 补查相关内容。
3. **编译**：
   - 新建或更新该素材的主题页（按上方 Schema）。
   - 更新被触及的**相关实体/概念页**：补要点、加互链、标矛盾。
   - **互链必须双向**：本页 `[[X]]` 出链写完后，**逐一到每个被链页面 X 的「相关页面」补回本页回链**——只写出链会造成单向链，lint 补锅滞后。
   - 更新 `wiki/index.md`（新页面登记，含一句话摘要）。
4. **记日志**：`wiki/log.md` 末尾追加：
   ```
   ## [YYYY-MM-DD] ingest | <主题页标题>
   - 来源: <raw 文档相对路径>
   - 新建: [页1, 页2]  更新: [页3, 页4]
   - 成本: ~N 轮工具调用 / 约 M tokens（粗估即可，用于观察规模化趋势）
   ```
5. **汇报**：列出本次新建/更新的页面清单与关键变化，等用户确认或继续。

**汇报格式（避免参考资料误报，必读）**：ingest 用了 `read_document`，会被参考资料机制认定为「检索」。汇报若只写操作日志（与源文档内容不重合），会触发「佐证不足」兜底 toast。因此汇报必须：
- 正文**包含该文档的内容摘要**（复用 wiki 页的摘要段），让正文与源文档内容重合；
- 末尾**带合规的 `## 参考资料` 章节**（`1. <源文档相对路径>`，纯相对路径、无 markdown 链接/行号），并在正文摘要处插 `[1]` 标注。
即：汇报 = 内容摘要（带 [1]）+ 操作清单 + `## 参考资料`，而非纯操作日志。

原则：**一次一篇，人工在环**——不批量摄入；编译时抓住要点而非全文搬运（wiki 页是蒸馏不是复制）。

## 操作二：Query 回填（答案沉淀）

触发：知识库问答产出了**有沉淀价值的综合型回答**（跨多文档的综合、对比、梳理），用户说「沉淀/回填到 wiki」，或你判断价值高时主动提议一次。

流程：把回答整理为 wiki 页（sources 填实际引用的文档），更新 index 与 log（op 为 `query`）。普通事实问答不回填——**只沉淀综合成果，别把 wiki 变成聊天记录**。

## 操作三：Lint（健康检查）

触发：「wiki lint」「检查 wiki 健康度」。

检查项（能机械化的用 kb_grep/grep 验证）：
- **断链**：wiki 页中 `[[...]]` 指向不存在的文件。
- **孤儿页**：除 index/log 外无任何入链的页面。
- **索引完整性**：wiki/ 下每个 .md（除 index/log）都在 index.md 中有条目。
- **过时标记**：页面 `updated` 早于其 `sources` 中文档的最新修改时间 → 建议重新摄入。
- **矛盾标记**：遗留的 ⚠️ 冲突标注未裁决。
- **互链缺口**：页面「相关页面」为空，但正文提及的主题已有对应 wiki 页（用 kb_grep 在 wiki/ 内搜该主题词验证）→ 提示补 `[[...]]` 互链（双向：对方页也应回链）。

输出：问题清单 + 修复建议；**简单修复（补索引、补互链）可直接做**，涉及内容改动的列出来等用户确认。完成后记 log（op 为 `lint`）。

## 与 knowledge-base 技能的关系

- 问答仍走 knowledge-base 技能；本技能只管 **wiki/ 的写入与维护**。
- 检索时 wiki 优先：`search_kb` 可先带 `paths=["wiki"]` 查成品知识；wiki 无覆盖再全库检索（知识库未收录时的回答不变）。
- wiki/ 在知识库根下，天然被 FTS 索引——wiki 页本身也是可检索内容。

## 边界

- 仅操作当前 workdir 下的 `wiki/`；**绝不修改 wiki/ 外的文档**。
- 摄入与 lint 的写入动作逐文件执行并汇报，不做无确认的大批量重写。
- wiki 规模控制在 ~100-200 页内体验最佳；超出时主题页合并/分层，仍靠 index + FTS 检索。
