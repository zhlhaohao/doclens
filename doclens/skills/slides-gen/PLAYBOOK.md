## 1. 提问细节（铁律 1-2 的展开）

### 每回合问什么（不说废话）

| 本轮做了什么 | 回合末问什么（每题 2-4 个 options） |
|---|---|
| 刚开工 | 缺口确认（P2 缺口 / 输出去向 / 事实口径） |
| 写完一版 | 「先看内容还是先调结构」→ 定稿 / 改某页 / 换主题 |
| 修完问题 | 「还要改哪里」→ 这页还有 / 下一页 / 定稿 |
| 出了验收报告 | 「全修还是只修 high」→ 全修 / 只修 high / 就这样 |
| 交付了成品 | 「还要调整吗」→ 改文字 / 换主题 / 加页 / 不用了 |
| 回答了咨询 | 「要我直接动手吗」→ 是 / 先不改 |

**兜底**：想不出问什么 → 问「下一步 A 还是 B」（A=最可能想要的），
或「按刚才说的执行吗」（执行 / 我要改）。**调用本身绝不能省。**

### 工具参数格式

```
questions: [
  {
    header: "输出去向",                     // ≤12 字
    question: "现有 11 页稿怎么处理？",      // 一句话
    multiSelect: false,
    options: [
      { label: "(Recommended) 新建一份",
        description: "旧稿原样保留，新建 slides/v1/内容稿.md" },
      { label: "直接改现有稿",
        description: "会覆盖已有 11 页内容，不可撤销" }
    ]
  }
]
```

- `label` 短（≤10 字），`description` 说清**选了的后果**
- ❌ `options: ["A", "B"]`（字符串数组，工具会拒）

### 两次真实事故（为什么规则这么严）

1. **零提问事故**（2026-10-29 会话 01M6383A…）：三次 `/slides-gen` 全程没问。
   旧闸门是条件式（「仅当用户没说才问」），长对话里模型总能找到"用户已说过"的依据 → 全跳过。
2. **表格提问事故**（同会话 seq=259）：问主题用 Markdown 表格列三套 +「告诉我选哪个」，
   用户只能手打「ink-magazine」。

**教训：条件式约束在长上下文里必然失效；文档格式会被照抄（模板写代码块里→回复就是代码块）。**

## 2. 复述细节（铁律 3-5 的展开）

复述用**正文有序列表**（❌ 不用代码围栏、不用表格）：

1. **主题**：一句话说清这次做什么
2. **我手上有什么**：已读到的文件，具体到文件名
3. **我的默认假设**：页数=… · 受众=… · 风格=… · 输出=<路径>

第 3 行缺口不写在正文里——直接放进 `ask_user_question`。

### 缺口要具体（❌ 空话 / ✅ 能直接答）

| ❌ | ✅ |
|---|---|
| 「请补充更多细节」 | 「试点范围：一个小组（5-8 人）还是全部门？」 |
| 「请确认方向」 | 「叙事主线用『数据主权』还是『效率优先』开场？」 |
| 「请确认风格」 | 「默认 corporate-blue；更硬朗用 swiss-grid，更深用 dark-tech？」 |

### 从零生成（用户只给了一个题目）

luobo generate.md 的核心方法，按此展开：

1. **先定一句话主张**——观众看完要记住的那句话（不是题目本身）。
   例如题目「AI 编程工具介绍」→ 主张「自研 agent 让团队把数据主权和效率同时拿到手」。
   这句话决定叙事主线和以后每一页的取舍。
2. **列 3-5 个支撑点**——每条都必须能回答「它怎么支撑那句话」；答不上来的砍掉。
3. **逐条查证后才写**（铁律 10）：涉及数据/现状/对比的，先 search_kb / web 查证；
   查不到的写「待确认」或留图位，**绝不编数字**。
4. 支撑点定稿后再套版式：单数字主张用 `big-number`，数据对比用 `stats`/`compare`。

页面节奏参考：口播/演讲约 1 页/25 秒（每页 ≤150 字），阅读型约 1 页/1.5 分钟。

### 故事线三型（支撑点排成叙事线时套用）

| 型 | 骨架（每格一页） | 适用 |
|---|---|---|
| **讲解型** | 钩子（为什么关注）→ 是什么 → 关键特性/差异 → 怎么用 → 已知的坑 → 号召 | 介绍新事物、产品发布 |
| **方案型** | 现状与痛点 → 目标 → 方案 → 实施计划 → 风险与对策 → 请拍板 | 汇报、申请资源、推方案 |
| **清单型** | 主张 → 条目 1..N（并列，每条独立成立）→ 收束 | 盘点、最佳实践、工具推荐 |

排线时对着模板逐格问「这页支撑哪一格」；多余的砍，缺的补。

### 图表取舍纪律

- **只罗列亮眼数字** → 用 `stats`/`big-number`，不上 chart
- **要看趋势/占比/对比** → 才上 `chart`；chart 页的 `source` 必填
- **chart 页标题 = 图里最重要的结论**（如「Q4 首次突破 3000 万」，不是「季度营收」）
- insights 列表补标题没说完的（标题说结论，insights 说依据）

### 口播备注写作纪律（notes）

- 一页 **40-260 字**（对应讲 15-60 秒）：写你要**说出口**的话，不是页面文字的复述
- **口语短句**：像说话一样写，别用书面长句
- **与页面一一对应**：页面出现的数据/图表，备注里要有它的解读
- **改写文章时保留作者原句和语气**——屏幕文字从备注里提炼，不是反过来
- 用户环境里有写作风格类技能（如 book-to-skill 装过的）→ 备注按那个风格写

### 场景 → 密度（自动推导，不问用户）

| 场景 | 密度 |
|---|---|
| 口播视频 / 现场演讲 | **低**（每页 ≤4 条、每条 ≤24 字，细节进 notes） |
| 发出去给人读 / 工作汇报 | **高**（按版式容量默认上限） |

## 3. 验收修复循环（铁律 8 的展开）

`build` 输出的问题分两类，修复策略不同：

| 来源 | 查什么 | 怎么修 |
|---|---|---|
| **geom（确定性）** | overlap / overflow / out_of_bounds / tiny_text / too_dense / accent_overuse | 按 `fix` 字段机械执行：拆页、删 20-30% 文字、列压到 3-4 |
| **vision（审美）** | misalign / whitespace / contrast / hierarchy / style | 多页同报 → 改版式或主题 CSS；单页报 → 改该页 md |

**修复纪律**：
- 同类问题改模板（layouts/*.html 或 base.css），不逐页改内容
- `overloaded`（缩到可读下限仍溢出）= 必须拆页，不是改样式
- 改完必须重跑 `build --pages <改动页>` 确认通过率上升

**视觉评分有抖动**（同页两次可能 72/86）——所以只有 `high` 和 `score<70` 阻断，
medium/low 只记建议；**不采信模型自报的 pass 字段**（实测与 score 矛盾）。

## 4. 降级处理（铁律 10 的展开）

### 视觉模型未配置 → 降级为纯几何

CLI 会打 ⚠ 警示块。交付话术必须区分：

> 几何层面已全部通过（无重叠、无裁切、字号可读），但**审美问题没有检查**——因为没配视觉模型。
> 配置方式：全局 .env 写 VISION_API_KEY 等四项，或设置页「模型」tab。

❌ 只说「全部页面通过」（几何通过 ≠ 视觉通过）
❌ 把 score 100 当结论（降级时报告显示 `—（未评估）`，100 是占位）

### 其他降级一览

| 场景 | 行为 | 你要做的 |
|---|---|---|
| mermaid 渲染器缺席 | 降级为代码块 + 警告 | 可接受，或提示装 mmdc |
| 未知版式/主题/图标 | 降级 + 警告 | check 期就该拦住，别等到渲染 |
| 图片缺失 | 虚线占位框 + 警告 | 用 `images` 查，重新生成或修路径 |
| `--open` 打开失败 | stderr 提示手动路径 | 告诉用户文件在哪 |

## 5. 话术模板

### 交内容稿（三句话各解决一件事）

> 改好了，你先看这版 —— **这是内容稿，还没做最终排版验收**。
> 你确认内容没问题，我再跑一遍完整检查（大概两三分钟），出正式交付稿。
> （然后调工具问「现在要改哪一页」）

### 交交付稿

> 内容定稿了，完整验收跑完：N 页全部通过 —— 几何无重叠无裁切、字号可读，
> 视觉评分 XX-XX。这版是最终稿，可以直接用。
> 五维自评：统一 X · 层级 X · 细节 X · 传达 X · 节奏 X，最弱是 XX。
> （然后调工具问「还要调整吗」）

### 幽灵稿确认

> 我按这条线排了 N 页，标题连起来是你的意思吗？顺序对不对？
> （然后调工具问「确认开工 / 调顺序 / 改标题」）

## 6. 反例集

> ❌ 每轮都 `build`：用户改一行字等 3 分钟，五轮 15 分钟 → 体验崩坏
> ✅ 内容稿 8 秒一版，满意才定稿

> ❌ 「已经生成好了，你看看」（不说版本性质）→ 用户拿草稿去汇报
> ✅ 「这是内容稿，确认后我出最终稿」

> ❌ 表格列三套主题 +「告诉我选哪个」→ 用户手打名字
> ✅ 发样张图 + 工具选项点选

> ❌ agent 直接对已有 deck 做 14 次 edit，改完才报「已生成」
> ✅ 动手前说「我将新建 slides/v1/xxx.md，不动旧稿」

> ❌ 一路跑到底：直接生成 12 页 → 交付，叙事线错了全白做
> ✅ 复述 + 幽灵稿确认后才渲染

## 7. 图位编号（重绘铁律）

- `P{页}-图{序号}` 是图位**永久身份**，换图不换号
- 旧图不删（用户可能反悔）
- `images` 显示 `local` 来源（真实截图）→ 重绘前**必须问**（AI 画不出真界面）
- 批量重绘只动 `jimeng` 来源的
