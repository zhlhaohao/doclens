# slides-gen — HTML 演示文稿生成技能

产物是**单文件 HTML**（双击即看、可转发、`←→` 翻页 / `N` 备注 / `F` 全屏 / `P` 打印 PDF）。

## 十一条铁律（先读这个，覆盖本文件一切其他表述）

1. **每回合必调 `ask_user_question`**：你的回复说完了话，就必须带一次工具提问（≤4 题一次问全）。用户说「你定/继续/可以了/改完了」也要问下一步。**说「已完成」绝不许自然结束。**
2. **问题只能在工具里**：正文不列选项、不编号、不用表格让用户手打。`options` 是 `{label,description}` 对象数组，第一项标 `(Recommended)`，header ≤12 字。
3. **动手前先复述**：正文发「①主题 ②我手上有什么 ③我的默认假设（页数/受众/风格/输出路径）」，然后问缺口，等回话。用户说「直接做」也照发。
4. **改文件前说去向**：新建 `<路径>` 还是改已有的 `<路径>`，用户没说改它时必须先问。**输出默认落盘到 `slides/` 目录**（md 源与 html 产物同目录），用户明确指定了位置才例外。
5. **零输入先要内容**：用户没给题目/文章/大纲时，先问做什么，**绝不自己编题目**。
6. **写完先 `check`**：ERROR 清零，把幽灵稿（纯标题清单）发用户确认叙事线，确认后才渲染。**不因「上下文已有大纲」跳过。**
7. **迭代给内容稿**（`render`+`qa --no-vision`，8 秒，落 `<名>-draft.html` 带徽标）；用户确认后 `build` 完整验收（3-5 分钟），**验收全过才写正式名 `<名>.html`**（不过时正式名保持上一版不动）。交付时说明是哪档。
8. **`build` 退出码 0 才算完成**：有 high 问题或 score<70 就改 md 重跑，直到全过。
9. **一页一个论点**：要点 ≤6 条、每条 ≤40 字，超了拆页不缩字号；颜色只写角色名；字号用标题层级表达。**标题里最关键的一个词用 `**加粗**`，一页最多标一处**（标多了等于没标）。**结尾页放结论或行动号召，不放「谢谢观看」**。
10. **事实必须查证**：涉及数据/产品现状/外部事实，先搜索或读库查证，**查不到的不写，绝不编数字**。拿不准就写「待确认」或留图位占位。
11. **降级必告知**：视觉模型没配上 → 明说「只做了几何检查，审美没查」；绝不把几何通过说成「全部通过」。

## 工作流

```
doctor（首次）→ 复述+提问 → 写 deck.md → check（幽灵稿确认）
→ 内容稿迭代（8 秒/版）→ 用户定稿 → build 完整验收 → 交付
```

两档交付：**内容稿** = render + 几何自检（8 秒，迭代用，落 `<名>-draft.html` 带徽标）；
**交付稿** = build 完整验收（3-5 分钟，含视觉审美 + 五维自评，rc=0 才写正式名 `<名>.html`）。

## 命令（agent 内部用，绝不教给用户）

| 命令 | 作用 |
|---|---|
| `doctor` | 环境自检（playwright/视觉API/字体/资产） |
| `analyze <素材>` | 素材结构 → 建议页数 |
| `check deck.md` | 写稿预检：容量/大纲/密度/对比度/图片版式主题合法性 + 幽灵稿 |
| `capacity` | 各版式容量表 |
| `preview deck.md` | 用用户自己的封面渲染三套主题样张（比报名字有效） |
| `gallery` | 版式样板间：19 个版式各渲染一页（总览图 + 翻页浏览页），供用户挑版式 |
| `extract-style <图>` | 参考图 → 主题 JSON（自动 WCAG 校准） |
| `render deck.md` | md → HTML（秒级） |
| `qa deck.html` | 视觉验收（`--pages 1,3` 只验指定页；`--no-vision` 只做几何） |
| `build deck.md` | render + qa（rc=0 = 全过） |
| `images deck.md` | 图位清单（重绘前必查：区分即梦生成/本地截图） |
| `pdf deck.html` | 导出 PDF（`--annotations` 带备注版） |

开发版从技能目录跑：`<venv>/python.exe -m renderer <子命令>`；发行版 `doclens slides-gen <子命令>`。

## 选版式（19 个，按内容形状）

| 形状 | 版式 |
|---|---|
| 2-4 个并列数据 | `stats`（2 列表格：值\|标签） |
| 里程碑/先后 | `timeline`（日期\|事件\|说明） |
| 两方对比 | `compare`（`---` 切两栏，首个加粗段作小标题） |
| 两个维度四象限 | `matrix`（3×3 表格） |
| 一个数字主张 | `big-number`（`number="3 倍"`） |
| 图文并排 | `image-left` / `image-right` |
| 并列要点 | `title-content`（默认）/ `two-col` |
| 2-6 张并列卡片（特性/目录网格） | `grid`（2 列表格：标题\|说明） |
| 目录/议程 | `agenda`（表格或列表，自动编号） |
| 层次结构（战略→执行） | `pyramid`（2 列表格，首行为顶层） |
| 转化漏斗 | `funnel`（阶段\|数值，自动算转化率） |
| 循环流程（PDCA/飞轮） | `cycle`（列表 3-5 节点，首尾箭头） |
| 收尾行动页 | `closing`（标题=决定请求，列表=下一步） |
| 封面/章节/引述/自由 | `title` / `section` / `quote` / `blank` |

**每页三件小事**：`takeaway`（一句话结论胶囊）、`kicker`（章节标签）、`source`（数据来源）。

## 设计预算（check/qa 会逐条查）

- 容量：要点 ≤6、每条 ≤40 字、总 ≤240 单元（`capacity` 查全表）
- 版式多样性：10 页以上至少 4 种版式、15 页以上至少 5 种；同版式不连排 3 页（`check` 会查，建议里直接给没用过的版式名）
- 字号：阶梯 22/20/17/15/13，最小 ≥16px，**不手写字号**
- 强调色 ≤3 处/页、面积 ≤8%；对比度 WCAG（正文 4.5:1、主色 3:1）
- 图标 `<i data-icon="zap"/>`，一页 ≤3 个；图位编号 `P3-图1` 是永久身份，**换图不换号**
- 图片：先 glob 查库内已有 → 无图才即梦生成（≥3 张先报数征得同意）→ local 截图重绘必须先问

## 按需深入（遇到对应场景再 read_file，不要一次全读）

| 场景 | 读这个 |
|---|---|
| 写 deck.md 之前（语法/指令/动画词/图表属性） | `SCHEMA.md` |
| 用户说了句模糊话，不知道怎么接 | `SCENARIOS.md`（90+ 条话术对照） |
| 验收报了问题怎么修 / 降级了怎么交代 / 看反例 | `PLAYBOOK.md` |
| 用户问字体兼容 | `FONTS.md` |

## 边界

- 只出 HTML + PDF；不做 HTML→PPTX、不做旧 pptx 换皮、不做反向解析
- 动画白名单封闭（飞入/淡入/缩放/擦除/强调），白名单外降级 fade
- 更复杂图表让用户出图后按图片引用
