# slides-gen — HTML 演示文稿生成技能

> 产物是 **单文件 HTML**（双击即看、可直接转发、支持点击翻页与动画、可打印成 PDF）。
> 不再产出 .pptx —— PPTX 无法保证版面不重叠，HTML 用 CSS 流式布局天然免疫。

## 工作流（五步 + 三道闸门）

```
0. 环境自检    slides-gen doctor   ← 首次使用先跑，缺组件当场报修复命令
              ┌─ 闸门 0：确认有素材 ⛔ —— 只有技能调用、没有任何内容时必须先要
                │          （绝不自己编题目）
1. 写 deck 源   <名>.md           ← 用 SCHEMA.md 的中间格式
                │  长文/大纲先用 analyze 看建议页数
                ┌─ 闸门 A：问定位（受众/场合/时长/风格）——仅当用户没说
2. 写稿预检    slides-gen check   → 容量/大纲/密度/对比度，秒级，不渲染
                └─ 闸门 B：幽灵稿确认 —— 必停 ⛔
3. 渲染+验收   slides-gen build   → <名>.html + 截图 + 评分 + 问题清单
4. 修复        按问题清单改 md（或版式/主题），重跑 3
5. 交付        报页数 + 用法 + 验收结论
```

**三道闸门是硬约束，不是建议**（细节见「提问决策点」章节）：

- **闸门 0（素材）**：用户只调用了技能、没给任何内容时，**先要内容**。
  绝不自己编题目往下做——做出一份没人要的 PPT 是最伤信任的事故。
  用户给了内容和用户没给内容，是两种完全不同的开局，别混。
- **闸门 A（定位）**：有了内容、但没说受众时，**先问一次**再动笔。
  受众决定深度，场合决定详略。顺序必须在闸门 0 之后（先知道做什么，再问给谁看）。
- **闸门 B（幽灵稿）**：`check` 跑完必须**停下来**，把 `<名>-outline.md` 的纯标题清单发给用户：
  「我按这条线排了 N 页，标题连起来是你的意思吗？顺序对不对？」
  **用户确认后才 build。** 这是最贵的一次返工点——叙事线错了，后面所有排版、配图、验收全白做。

> 豁免：用户明确说「直接做 / 不用问 / 你定」，或明显异步（给完需求就不再回话）时，
> 跳过闸门 A 与 B，**交付时列出你做的选择**（主题、页数、配图来源）。
> **但闸门 0 不豁免**——「直接做」也总得先有个题目，否则无内容可做。

**第 2 步别跳**：容量超载/标题不像结论这类问题，`check` 一秒就能发现；等渲染+视觉验收（分钟级）才发现就白跑一轮。

**第 4 步是硬门槛**：`build` 退出码 0（全部页面通过）才算完成。用户看的是最终画面，不是源码。

### 命令（按当前实例身份选，双形态）

开发版（python = `../cortex/.venv/Scripts/python.exe`，数据目录 `.cortex`）：

```bash
cd <技能目录>            # doclens/skills/slides-gen
<python> -m renderer build "<deck.md>" -o "<deck.html>"
```

发行版（`doclens slides-gen ...`，数据目录 `.doclens`）：

```bash
doclens slides-gen build "<deck.md>" -o "<deck.html>"
```

子命令：

| 命令 | 作用 | 耗时 |
|---|---|---|
| `doctor` | 环境自检：playwright / 视觉 API / 字体 / 资产完整性，给中文修复建议 | 秒级 |
| `analyze <素材>` | 素材结构分析：字数/小节/数据点 → **建议页数** | 秒级 |
| `extract-style <图>` | 参考图 → 主题 JSON（自动提色 + WCAG 校准） | 秒级 |
| `check deck.md` | 写稿期预检：容量/大纲/结构/密度/主题对比度，产出幽灵稿 | 秒级 |
| `capacity` | 打印各版式容量表（要点数/单条字数/总字数/表格行列） | 即时 |
| `render deck.md` | md → HTML | 秒级 |
| `qa deck.html` | 对已生成 HTML 做视觉验收 | 分钟级 |
| `build deck.md` | = render + qa（一键） | 分钟级 |

常用参数：`--pages 1,3-5` 只验指定页 ｜ `--no-vision` 只跑几何自检 ｜ `--no-embed` 图片不内嵌 ｜ `--theme X` 临时换主题

## 验收闭环（本技能的核心，务必执行）

`build` 会产出：

| 产物 | 位置 | 用途 |
|---|---|---|
| 截图 | `<name>-qa/pXX.png` | 每页 2x 放大截图，可直接看 |
| 报告 | `<name>-qa/report.md` | 人类可读的问题清单（含修复建议） |
| JSON | `<name>-qa/report.json` | 结构化 issues，便于批量处理 |

问题分两类来源：
- **geom（几何自检，确定性）**：元素重叠、内容裁切、越出安全边距、字号过小、图片变形、信息密度
- **vision（视觉模型，审美）**：对齐失衡、留白怪异、对比度不足、层级不清、观感不专业

**修复纪律**：
1. **先看截图再改**——用 read_file 看不了 png，但报告里的 detail 已描述清楚位置与现象
2. **同类问题改模板，不逐页改内容**——若多页都报「内容偏上/留白失衡」，改 `assets/base.css` 或对应 `layouts/*.html`；只有单页问题才改 md
3. **内容超量就拆页，不要靠缩字号硬塞**——报告里的 `too_dense` / `overflow` 优先拆页
4. **修改后必须重跑 build**，确认通过率上升；直到 `全部页面通过`

## 设计规则（写稿时就要遵守，`check` 会逐条查）

### 选版式（13 个，先想内容形状）

| 内容形状 | 用这个版式 |
|---|---|
| 一句结论 + 一个数字 | `big-number`（`number="3 倍"`） |
| 2-4 个并列数据 | `stats`（2 列表格：值 \| 标签） |
| 有先后顺序的里程碑 | `timeline`（3 列表格：日期 \| 事件 \| 说明） |
| 两方对比取舍 | `compare`（`---` 切两栏，首个加粗段作小标题） |
| 两个维度切四象限 | `matrix`（3×3 表格） |
| 图文并排 | `image-left` / `image-right` |
| 并列要点/清单 | `title-content`（默认）/ `two-col` |
| 封面/章节/引述/自由排 | `title` / `section` / `quote` / `blank` |

**关键**：`stats`/`timeline`/`matrix`/`compare` 不需要特殊语法——用普通表格和列表写，
渲染器按形状还原。所以正常写 Markdown 即可，别去发明新标记。

### 每页都该有的三件小事

- `takeaway`：这一页的**一句话结论**（页底胶囊）——没有它，页面就只是罗列
- `kicker`：章节标签（如 `01 · 数据`），帮听众定位
- `source`：数据来源，专业度直接拉满

### 一页装多少（容量表）

每页的容量写在各版式 HTML 的 `data-cap` 里，`slides-gen capacity` 可查全表。核心几条：

| 版式 | 要点数 | 单条字数 | 本页总字数 | 表格 |
|---|---|---|---|---|
| title-content（默认） | 6 | 40 | 240 | 8 行 × 4 列 |
| two-col | 8（两栏合计） | 34 | 260 | 6 × 3 |
| image-left / image-right | 5 | 34 | 200 | 4 × 3 |
| title / section / quote | — | — | 60~90 | — |

**超了怎么办**：拆页 > 删减 20-30% > 换更宽松版式。**绝不靠缩小字号硬塞**——autofit 有可读性下限，缩到底仍溢出就会判「必须拆页」，白跑一轮。

### 字号阶梯（不要手写字号）

全 deck 共享一套档位，autofit 只在这些档位间切换：`body 22 → 20 → 17 → 15 → 13`。
**你不需要也不应该写任何字号**——用 `#`~`####` 表达层级，字号由主题阶梯 + autofit 决定。

### 孤字

中文折行后末行只剩 1-2 字（「任」字吊在末行）是排版瑕疵。已用 `text-wrap: pretty` 自动规避；若版式特殊导致仍出现，降一档字号或改写句子。

### 强调色预算

单页 accent 色**≤ 3 处**、着色面积 **≤ 版面的 8%**。这是几何自检的确定性规则（不是审美偏好）。
强调遍地等于没有强调——一页只留最关键的一处。

### 对比度预算

主题色板在 `check` 时做 WCAG 校验：正文/背景 ≥ 4.5:1，主色与强调色/背景 ≥ 3:1。
自定义主题不达标会警告并指出该调哪个色。

### 图标（81 个内置）

行内写 `<i data-icon="zap"/>`，渲染为 inline SVG，颜色随所在文字（`currentColor`）。

```markdown
- <i data-icon="zap"/> **快** — 性能提升 3 倍
- <i data-icon="shield"/> **稳** — 99.99% 可用性
```

常用语义（全表见 `assets/icons.json` 或打开 `assets/icons-preview.html` 目检）：
`zap` 速度 · `shield` 安全 · `lock` 私有 · `eye` 可见/审计 · `layers` 架构 · `database` 数据 ·
`trending-up` 增长 · `target` 目标 · `check` 完成 · `alert` 风险 · `users` 团队 · `rocket` 上线 ·
`workflow` 流程 · `puzzle` 技能 · `home` 本地 · `cloud` 外部 · `scale` 对比 · `lightbulb` 洞察

规则：**一页图标不超过 3 个**（多了变装饰噪音）；图标是语义补充，不能替代文字。写不存在的名字会被忽略并警告。

### 五维自评（`qa` 自动产出）

整册评审给五个维度打分（0-10）：**统一 / 层级 / 细节 / 传达 / 节奏**，并指出最弱一维与整册最该改的 1-3 条。
这些分**不阻断**（阻断靠 high 问题与单页 score<70），但交付时必须把分数和最弱项报给用户。

## 提问与停顿点

### 流程表（哪些步要停下来）

| 步 | 做什么 | 停下确认 | 确认物 |
|---|---|---|---|
| **0** | **判断素材**（动笔前第一件事） | **是 ⛔**（零输入时必须停下来要内容） | 见「0. 素材检查」 |
| 1 | 写 deck 源 | 视情况 | — |
| 1b | **问定位**（受众/场合/时长/风格） | **是**（仅当用户没说清） | 一次提问，见下 |
| 2 | `check` 预检 | **是 ⛔** | `<名>-outline.md` 幽灵稿 |
| 2b | **出风格样张** | **是**（仅当没说风格） | `previews/sheet.png` 三套对比图（当前主题 + 两套反差大的） |
| 3 | `build` 渲染+验收 | 否 | — |
| 3b | **出图前确认**（≥3 张） | **是** | 图位清单（页/用途/张数） |
| 4 | 修复 | 否 | — |
| 5 | 交付 | — | 见「交付话术」 |

用户说「直接做 / 不用问 / 你定 / 赶时间」→ **全部跳过**，用默认值，
自动取第一套风格样张，交付时列出做过的选择。

### 0. 素材检查（第一件事：先确认有内容可做）

**绝不自己编题目。** 用户只说「做个 PPT」「帮我做个汇报」时，第一句应该问「做什么」，
而不是问「给谁看」——顺序反了用户会莫名其妙（他还不知道你要做什么）。

| 用户给了什么 | 怎么做 |
|---|---|
| 题目 | 进入「1b 问定位」；内容自己查证补充（**查不到的不写**） |
| 文章 / 口播稿 / 大纲 / 旧 md | 先 `analyze` 看结构（字数/小节/建议页数），再问定位 |
| 旧 `.pptx` | 说明**本技能不做换皮**，请他给文字内容或大纲；或用 doclens 的 `read_document` 先取出文本 |
| 一堆零散素材（链接、截图、几个要点） | 先 `analyze` 汇总，缺什么问什么 |
| **什么都没给** | **停下来要内容 ⛔**，用下面的标准话术，别猜 |

**零输入标准话术**（一次说完，给 4 个选项 + 3 个可选参数）：

> 做 PPT 需要先有内容，任选一种给我：
> 1. **一个题目** —— 如「公司 AI 工具落地方案」，我来搭结构（数据会查证，查不到不写）
> 2. **一篇文章 / 文档** —— 我来提炼论点、决定分页
> 3. **一份大纲** —— 我按你的骨架填内容
> 4. **已有的 md** —— 我改现有稿子
>
> 另外三项可选，不说我用默认：给谁看（默认有基础的同事）／讲多久（按素材估）／要不要演讲备注（默认要）

**用户答了内容之后，才问定位（1b）。** 两者不要合并成一问——一次问 9 个问题没人答得动。

**边界**：用户说「随便做个」「你看着办」时，仍要先要一个题目；只有他明确说
「你自己定个题目」才允许自拟，且交付时必须说明「题目是我拟的，可替换」。

### 0. 问需求（一次问完，每项带默认值）

**封闭枚举，用户不回答就用括号里的默认值，绝不追问第二遍。**

- 用在哪里：口播视频 / 现场演讲 / 发出去给人读 / 工作汇报（**现场演讲**）
- 给谁看：小白 / 有基础 / 专业同行 / 老板（**有基础**）
- 多长：几分钟或几页（**按素材估，约 1 页 / 1.5 分钟**）
- 风格：有参考图 → 走自定义；没有 → 出三张样张挑（**出样张**）
- 要不要演讲备注（**口播和演讲默认要，纯阅读稿可省**）

### 场景 → 密度（自动推导，不要问用户）

| 场景 | 密度 | 含义 |
|---|---|---|
| 口播视频 / 现场演讲 | **低** | 一页一个观点，屏幕字少，展开的话全放 notes |
| 发出去给人读 / 工作汇报 | **高** | 一页能独立看懂，可多放几条，notes 简短 |

低密度：每页要点 ≤4 条、每条 ≤24 字、正文总量 ≤150 单元（`check` 的 `density/过密` 门槛对低密度页收紧）。
高密度：按版式 `data-cap` 默认上限执行。

### 2b. 出风格样张（比报主题名有效得多）

用户没说风格、也没有参考图时：**不要用文字报「商务蓝 / 瑞士网格」让用户瞎选**——
用**他自己的封面和首页内容**渲染三套，拼成一张对比图给他看。

```bash
slides-gen preview <deck.md>              # 稳妥 / 大胆 / 意外 各一套
slides-gen preview <deck.md> --themes a,b,c   # 指定三套
```

产出 `previews/sheet.png`（三行，每行一套主题的封面+内容页），
发给用户并说明「第一行稳重适合汇报、第二行有冲击力适合发布、第三行偏文艺适合分享」。

用户选定后改 frontmatter `theme: <名>` 再继续。

### 3b. 出图前确认（最花钱的一步）

需要生成 **≥3 张**配图时，先把图位清单发给用户：

```
将生成 3 张配图：
  P2-图1 数据堡垒图标      （即梦）
  P5-图1 增长趋势示意      （即梦）
  P7-图1 团队协作场景      （即梦）
约 2-3 分钟。可以开始吗？
```

用户同意后再批量调即梦。**单张重绘不需要确认**（用户已明确要求）。

### 必须问 vs 不必问

**必须问**（做错要大幅返工 / 花真钱）：
定位不清 · 幽灵稿 · 风格无偏好 · 批量生图 ≥3 张 · 重绘 local 截图 · 推倒重做 · 覆盖已有文件 · 边界外请求

**不必问**（直接做）：
改文字/数字/措辞 · 重绘已指定编号的 jimeng 图 · 修 high 问题 · 用户已说过的主题 ·
调页序/增删页/拆页 · 加图标/改对齐/换版式 · 主题有哪几套、容量多少、图在哪（`capacity`/`images` 一条命令就有）

### 怎么问

1. **一次问全**：`ask_user_question` 一次最多 4 题，不挤牙膏
2. **给推荐**：推荐项放第一位并说明理由
3. **带默认值**：「你不回答我按 X 做」
4. **别问能自己查的**

### 反例

> ❌ 一路跑到底：直接生成 12 页 → 交付。叙事线错了用户只能推翻
> ✅ 停一次：「我按『为什么自建 → 怎么建 → 成本收益』排了 8 页，标题清单如下，确认顺序？」

> ❌ 报主题名：「可选 corporate-blue、swiss-grid、ink-magazine」→ 用户看不懂
> ✅ 出样张：`preview` 渲染他自己的封面三版 → 「你看哪版更像你要的？」

> ❌ 挤牙膏：「给谁看？」→「什么场合？」→「多长时间？」（三次往返）
> ✅ 一次问全：「①用在哪 ②给谁看 ③讲多久（不答我按现场演讲/有基础/按素材估）」

## 两阶段交付：内容稿 → 交付稿

用户改内容往往要来回好几轮。每轮都跑完整验收（3-5 分钟）会让体验崩坏。
所以分两档，**成本差 40 倍**：

| | 内容稿（迭代用） | 交付稿（定稿用） |
|---|---|---|
| 跑什么 | `render` + `qa --no-vision` | `build`（完整验收） |
| 耗时 | **约 8 秒** | 约 3-5 分钟 |
| 查什么 | 重叠 / 裁切 / 溢出 / 最小字号 / 密度 | 上面全部 + 视觉审美（留白/层次/对比度/配色）+ 五维自评 |
| 修到全过 | 否 | **是**（rc=0 才交付） |
| 给用户的话 | 「内容稿，还没做最终验收」 | 「最终稿，可以直接用」 |

### 什么时候用哪档（不用问用户，自己判断）

- 用户说「先改内容」「先别生成」「内容还没定」→ **内容稿**
- 用户在反复微调（第 2 次以上修改）→ **内容稿**
- 用户说「可以了」「出成品」「就这样」「发我」→ **交付稿**
- 用户明确要 PDF → 必然先跑交付稿（PDF 是成品形态）

### 内容稿阶段为什么仍要跑几何自检

只 `render` 是 2 秒，但用户可能看到字溢出、元素重叠的烂版面，直接失去信任。
多花 6 秒跑 `qa --no-vision`，能挡住硬伤——而且这些硬伤大多**是内容量问题**
（字太多、要点太长），正好是内容阶段该发现的。审美问题留到定稿。

### 话术模板

**交内容稿**（三句话，各解决一件事）：

> 改好了，你先看这版 —— **这是内容稿，还没做最终排版验收**。
> 你确认内容没问题，我再跑一遍完整检查（大概两三分钟），出正式交付稿。
>
> 现在要改哪一页？

- 「这是内容稿」→ 用户知道可以大胆改
- 「还没做最终验收」→ 用户不会拿草稿去汇报
- 「确认后我再跑」→ 给出定稿的明确触发点，且预告会变慢

**交交付稿**：

> 内容定稿了，完整验收跑完：N 页全部通过 —— 几何层面无重叠、无裁切、字号可读，
> 视觉评分 XX-XX。这版是最终稿，可以直接用。

### 反例

> ❌ 每轮都 `build`：用户改一行字等 3 分钟，改五次等五轮，体验崩坏
> ✅ 内容稿 8 秒一版，改到满意才定稿

> ❌ 只给文件不说版本性质：「已经生成好了，你看看」——用户以为是成品，拿去汇报发现排版没验
> ✅ 「这是内容稿，你确认后我再出最终稿」

> ❌ 只说「这个还没验收」——用户不知道该不该信
> ✅ 「还没做最终验收」+ 说清差什么（视觉审美）+ 说清什么时候补（确认内容后）

### 纯标题阶段（更早的一档）

用户连内容都还没定、只想先看结构时：只跑 `check`（秒级），
把 `<名>-outline.md` 的标题清单发过去——不含正文，纯叙事线确认。

## 常见场景配方（用户说人话，你去调命令）

> **不要教用户记命令。** 用户只会说「第 3 页那张图不好看」，你去 `images` 查编号、
> 调即梦重绘、改 md、`build --pages 3`。命令是你自己的工具。
>
> 全量话术对照表见 **SCENARIOS.md**（含模糊表达澄清、边界外回应、交付前自查清单）——
> 拿不准用户想干什么时先查它。

### A. 按输入给料

| 用户说 | 你怎么做 |
|---|---|
| 「我只有个大纲，做成 PPT」 | **大纲模式**：标题直取大纲项（改写成结论句但保留原意），跳过故事线设计，notes 可留空。写完必须 `check` |
| 「题目是 XX，做个 5 分钟的」 | 先问 1 次受众/场合 → 时长换算页数（约 1 页/1.5 分钟，5 分钟 ≈ 4-6 页）→ 生成模式 |
| 「把这篇文章做成 PPT」 | 提炼论点 → 每页一个结论式标题 → `check` → `build` |
| 「这个 md / html 再改改」 | 已有 md 直接改；只有 html 说明源 md 丢了，问用户要不要从 html 反推（不推荐，html 是产物） |
| 「照这份旧 PPT 的内容做一份新的」 | **不做 pptx 换皮**（本技能边界）。改用文字：让用户给大纲或复制要点，走大纲/生成模式 |

### B. 改内容（全部：定位 → 改 md → `build --pages n`）

| 用户说 | 你怎么做 |
|---|---|
| 「第 3 页文字改一下」 | 读 md 找该页 → 改文字 → `build --pages 3` |
| 「第 5 页太挤了」 | `capacity` 查更宽松版式 → 改该页 `layout=` → `build --pages 5` |
| 「第 2 页太单薄」 | 补要点/数据/配图，或换 `image-right` 加图 → 再 `check` 看密度 |
| 「这两页顺序调一下」 | 交换 md 中两个 `<!-- slide: -->` 段 → `build` |
| 「在中间加一页讲 XX」 | 插入新页（含页指令）→ `check` → `build` |
| 「删掉第 6 页」 | 删该段 → `build`（页码自动重排） |
| 「这页验收报的错修一下」 | 读 `<name>-qa/report.json` 的 issues → 按 `fix` 字段改 → `build --pages n` |

### C. 换风格

| 用户说 | 你怎么做 |
|---|---|
| 「整体换个深色的」 | 改 frontmatter `theme: dark-tech` → `build` |
| 「换主题后图不搭了」 | 走 D 的重绘流程（只重绘 jimeng 来源的图，本地截图不碰） |
| 「看看有哪些风格」 | 列 8 套主题名 + 一句话特征；`--open` 让用户直接看 |
| 「按这张参考图的配色来」 | `extract-style <图> --name <名>` 自动提色 + 对比度校准（照片类会提示加 `--bg '#FFFFFF'`）→ frontmatter 写 `theme: <名>` → `check` 复核 |

### D. 处理配图（重点场景）

**第 1 步永远是 `images <deck.md>`**——拿到图位编号、来源、路径的清单。

| 用户说 | 你怎么做 |
|---|---|
| 「第 3 页那张图不好看，重画」 | `images` 找 `P3-图1` → 确认来源是 jimeng → 换 prompt 调 `mcp__jimeng__generate` → `edit_file` 只改该行路径（**alt 里的 P3-图1 不动**）→ `build --pages 3` |
| 「所有配图都不满意」 | `images` 列清单 → 只重绘 `jimeng` 来源的（`local` 是用户截图，先征询）→ 逐张生成 → `build` |
| 「这张图换更简洁的风格」 | 在原 prompt 基础上加风格词（「极简/白底/少细节」）→ 重生成 → 换路径 |
| 「这页不要图，改纯文字」 | 删该图片行 → 换 `title-content` 版式 → `build --pages n` |
| 「加一张图」 | 先 glob 查知识库已有图（`图片/AI/`）→ 无则即梦生成 → 插 `![P{n}-图{k} 用途](路径)` → 换 `image-left/right` 版式 |
| 「图丢了/显示占位框」 | `images` 看 `缺失!` 项 → 重新生成或改到正确路径 |
| 「图片太多导致装不下」 | `images` 看有几张 → 删次要的，或拆页 |

**重绘铁律**：
- 编号 `P{页}-图{序号}` 是图位永久身份，**换图不换号**
- 旧图不删（用户可能反悔）
- 本地截图（`local` 来源）重绘前必须问用户——那是真实产品截图，AI 画不出来

### E. 交付形态

| 用户说 | 你怎么做 |
|---|---|
| 「给我个 PDF 发邮件」 | `pdf <deck.html> -o <名>.pdf` |
| 「要带备注的内部复盘稿」 | `pdf --annotations`（每页底部附演讲备注） |
| 「我看看效果」 | `build --open` |
| 「会议室投屏用」 | frontmatter 加 `projection: true`（字号下限抬高、容量自动收紧）→ 说明「投屏时按 F 全屏」 |
| 「手机上也要能看」 | 说明移动端手势已支持（滑动翻页）；`--open` 后用户可直接手机访问 |

### F. 用户提出技能做不到的事

| 用户说 | 你怎么做 |
|---|---|
| 「导出成 PPTX，我要发给甲方」 | 说明本技能只出 HTML + PDF；PDF 可直接发；若必须 pptx，建议用别的工具转换并说明会有损 |
| 「帮我把这份旧 PPT 美化」 | 不在边界内。可提取文字后重新做（走大纲模式） |
| 「加个路径动画/陀螺旋」 | 动画白名单封闭，说明支持哪些（飞入/淡入/缩放/擦除/强调），其余降级为淡入 |

## 中间格式速查（详见 SCHEMA.md，写之前必读）

- frontmatter：`theme`（clean-white/corporate-blue/dark-tech/warm-paper）、`size`（16:9/4:3/A4）、`title`、`author`、`anim`、`transition`
- 分页：`<!-- slide: layout=... transition=... anim=... bg=... notes="..." -->`
- 块级：`<!-- block: anim=... align=... fit=... style=... chart=... x= y= w= h= color=... -->`
- 正文 = 合法 CommonMark + 行内白名单 `<mark>` `<span class="角色名">` `<br>`
- 动画：`enter.fly-in`（direction=left/right/up/down）/ `enter.fade` / `enter.zoom` / `enter.wipe` / `exit.fly-out` / `emphasize.pulse` / `emphasize.grow`
- 图表：`<!-- block: chart=bar|line|pie -->` + 紧随的 MD 表格（渲染为内联 SVG）
- two-col 版式里 `---` 是栏切分符，不是水平线

## 内容生成纪律

1. **一页一个论点**：要点 ≤ 6 条、每条 ≤ 40 字；超了就拆页——这是通过验收的第一前提。
2. **版式优先**：先定每页版式（8 选 1），不要用 blank+坐标手排（除非用户明确要精确排版）。
3. **颜色只写角色名**（primary/accent/…），不写十六进制。
4. **字号不手写**：用 `#`~`####` 标题层级，字号走主题阶梯。
5. **notes 常写**：`notes="..."` 写演讲提示，几乎零成本。
6. **图片三级流程**（按序执行，省 token）：
   a. **先检测**：glob 搜知识库已有图片（优先 `图片/AI/`），契合的直接引用，**不重复生成**；
   b. **无图才生成**：调 `mcp__jimeng__generate`（prompt 写清画面内容与风格，匹配 deck 主题），落盘后引用返回路径；
   c. **重生成**：用户不满意 → 同一画面意图换 prompt 重调（新文件落盘），改 md 引用；不删旧图。
   图片 alt 必须带图位编号（`![P3-图1 架构图](...)`）——编号是图位永久身份，重生成只换路径不换编号。

### 视觉降级时必须说（不许含糊）

`qa` / `build` 输出里出现 ⚠ 视觉验收未执行 的警示块时，**交付话术必须明确区分两件事**：

| 已做 | 未做 |
|---|---|
| 几何检查：重叠 / 裁切 / 边距 / 字号 / 密度 / 强调色预算 / 图片变形 | 审美检查：留白 / 层次 / 对比度 / 配色 / 整体观感 |

**必须说**：「几何层面已全部通过（无重叠、无裁切、字号可读），但**审美问题没有检查**——因为没配视觉模型。」
**必须给**：配置方式（全局 `.env` 写 `VISION_API_KEY` 等四项，或设置页「模型」tab），并提议配好后重跑。

**禁止**：
- ❌ 只说「全部页面通过」——几何通过 ≠ 视觉通过
- ❌ 不提降级就直接交付——用户会以为已经过视觉验收
- ❌ 把 `score 100` 当结论——降级时根本没有评分（报告显示 `—（未评估）`）

对应 `report.md` 顶部有固定警示段，交付时照抄即可。

### 常见降级原因

| 原因 | 判断 | 处理 |
|---|---|---|
| 没配视觉模型 | `doctor` 报「✗ 视觉模型配置」 | 告诉用户怎么配 |
| 用了 `--no-vision` | 主动关闭 | 说明这是调试用法，正式验收要开 |
| 模型调用失败（超时/限流/401） | 报告里有 `qa_error` | 报具体错误，建议重试或换模型 |

## 交付话术

渲染+验收通过后，向用户报告：
- 产物路径 + 页数（用户要 PDF 就一并给 PDF）
- **怎么演示**：双击打开；方向键或点击翻页；`N` 看演讲备注；`F` 全屏；`P` 打印
- 验收结论：几页、全部通过、五维自评分数与最弱一项
- 用了即梦的，说明哪几页是 AI 配图；缺图的如实说

**只说「演示时按什么键」，绝不说「运行 slides-gen xxx 命令」。**
用户不需要知道技能内部有 check/render/qa/build/images/pdf——
他们只会说「改第三页」「换张图」「给我 PDF」，这些是你要翻译成命令，不是要用户记的。

反例（不要这样交付）：
> ❌ 你可以用 `slides-gen build deck.md --pages 3` 重新生成第三页
> ✅ 第三页已经改好并验收通过了，你再看看效果

## 边界

- 只产出 HTML + PDF；不做 HTML → PPTX / PPTX → MD 反向转换
- 动画白名单封闭（见 SCHEMA.md §5），白名单外的词降级为 fade
- 图表仅 bar/line/pie；更复杂图表让用户出图后按图片引用
- 打印分页在 Chrome/Edge 下最稳；`pdf` 命令走 headless Chromium，与浏览器打印等效
- 字体由打开者的机器渲染，主题用回退链（见 FONTS.md）；依赖非系统字体时交付要提醒
