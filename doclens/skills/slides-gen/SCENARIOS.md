# slides-gen 用户话术对照表

> 用途：把用户各种说法映射到技能动作。
> **面向 AI 读者**（agent 查表执行）；用户永远说人话，命令只在内部使用。
> 用户不会说「运行 build --pages 3」，只会说「第三页改一下」。

---

## 零、什么都没给（最高频的坏开局）

用户只调用了技能，或只说「做个 PPT」「帮我做个汇报」，没有给任何内容。

**铁律：先要内容，绝不自己编题目。** 顺序是「先问做什么」→「再问给谁看」，不能反。

| 用户原话 | 意图 | agent 动作 |
|---|---|---|
| （只有技能调用，无任何文字） | 空输入 | **停下来要内容 ⛔**，用下面的标准话术 |
| 「做个 PPT」 | 空输入 | 同上 |
| 「帮我做个汇报 PPT」 | 空输入 | 同上 |
| 「随便做个」「你看着办」 | 含糊 | 仍要先要一个题目；只有明确说「你自己定题目」才可自拟，且交付时说明「题目是我拟的」 |
| 「你帮我定题目吧」 | 授权自拟 | 可自拟题目，但**必须**在交付时说明并给替换机会 |
| 「之前的那个 PPT 还能改吗」 | 找旧稿 | 用 `glob` 找 `<名>.md`；有则改，只有 html 则说明源文件丢了、建议重做 |

**标准话术（一次说完，4 个选项 + 3 个可选）**：

> 做 PPT 需要先有内容，任选一种给我：
> 1. **一个题目** —— 如「公司 AI 工具落地方案」，我来搭结构（数据会查证，查不到不写）
> 2. **一篇文章 / 文档** —— 我来提炼论点、决定分页
> 3. **一份大纲** —— 我按你的骨架填内容
> 4. **已有的 md** —— 我改现有稿子
>
> 另外三项可选，不说我用默认：给谁看（默认有基础的同事）／讲多久（按素材估）／要不要演讲备注（默认要）

**为什么不能合并成一问**：内容 + 定位 + 风格加起来 9 个问题，用户答不动；
而且没确定题目时问受众，用户会觉得莫名其妙（他还不知道你要做什么）。

## 一、按输入给料

| 用户原话（真实说法） | 意图 | agent 动作 |
|---|---|---|
| 「我只有一个大纲，帮我做成 PPT」 | 大纲 → deck | **大纲模式**：标题直取大纲项、改写为结论句但保留原意；跳过故事线设计；notes 可留空；写完 `check` |
| 「这是我们会议的议题清单，排成片子」 | 同上 | 同上；清单项若过密，先分组再分页 |
| 「就一个题目：XX，做个五分钟的」 | 题目 → deck | 先问 1 次「给谁看、什么场合」；时长 ÷ 1.5 ≈ 页数（5 分钟 ≈ 4-6 页）；再走生成模式 |
| 「题目是 AI 编程工具，随便做做」 | 题目 → deck（低要求） | 不问细节直接做，选一套安全主题（corporate-blue），交付时说明「按默认假设做的」 |
| 「把这篇文章做成 PPT」 | 长文 → deck | 提炼 5-8 个论点 → 一页一论点 → 结论式标题 → `check` → `build` |
| 「这份周报转成汇报片」 | 结构化文档 → deck | 按原有小节分页；数据做成图表块；原文细节移进 notes |
| 「照着这个 md 改改」 | 已有 deck 源 | 直接编辑该 md → 局部 `build --pages` 或全量 `build` |
| 「上次那个 PPT 还有吗，再给我一版」 | 复用旧稿 | 先 glob 找 `<名>.md`；有则改，只有 `.html` 则说明源文件丢失、建议重做 |
| 「把这份旧 PPT 的内容搬过来重做」 | pptx 内容 → 新 deck | **不做换皮**（边界外）。请用户给文字大纲或复制要点；也可先用 doclens 的 pptx 解析能力取出文本 |
| 「这是竞品的 PPT，照这个内容做」 | 同上 | 同上；只借内容不借版式（版式由本技能主题决定） |
| 「我们老板给了这 20 页 Word，压缩成 10 页」 | 精简 | 先提炼主线 → 合并同类 → 每页一个结论 → `check` 密度与容量 |

## 二、改内容

| 用户原话 | 意图 | agent 动作 |
|---|---|---|
| 「第三页文字改一下」 | 改文案 | 读 md 定位第 3 页 → 改 → `build --pages 3` |
| 「第三页那个标题不行，太长了」 | 改标题 | 压成 ≤22 字结论句 → `check` 看 `outline/标题过长` 是否消失 → `build --pages 3` |
| 「第三页太挤了」 | 内容超载 | `capacity` 查更宽松版式 → 改该页 `layout=`；仍不够就拆页 → `build --pages 3` |
| 「这页太空了，撑不起一页」 | 密度不足 | 补支撑要点/数据/配图，或换 `image-right` 加图 → `check` 看 `density/过稀` |
| 「这页看着乱」 | 版式不适配 | 换版式（列表→卡片式用 two-col；对比用 two-col；引述用 quote）；先看 `check` 有无 `structure/版式重复` |
| 「这两页顺序反了」 | 调序 | 交换 md 中两段 `<!-- slide: -->` → `build`（页码自动重排） |
| 「中间加一页讲竞品」 | 插页 | 插入新页（含页指令）→ `check` → `build` |
| 「把第五页删掉」 | 删页 | 删该段 → `build` |
| 「第七页拆成两页」 | 拆页 | 按逻辑切分内容 → 各自加页指令 → `check` 验容量 → `build` |
| 「这页和上一页重复了」 | 去重 | 合并或删一页 → 检查 `structure/版式重复` |
| 「补一页总结」 | 加收尾页 | 用 `title` 或 `quote` 版式做收尾 → `build --pages n` |
| 「这页的表格看不清」 | 表格过密 | 列压到 3-4 列、行压到 7 行内；或改图表块 → `build --pages n` |
| 「数字错了，应该是 320」 | 改数据 | 改 md（表格或正文）→ 注意「图表数据改了，标题结论要跟着改」→ `build --pages n` |
| 「这个说法太绝对，缓和一点」 | 措辞 | 改文字；不动结构 → `build --pages n` |
| 「加个目录页」 | 加 toc | 在封面后插一页 `section` 或列表式目录 → `build` |
| 「第一节和第二节之间加个过渡页」 | 加章节页 | 插 `section` 版式页 → `build` |

## 三、换风格

| 用户原话 | 意图 | agent 动作 |
|---|---|---|
| 「整体换个深色的」 | 换主题 | frontmatter `theme: dark-tech` → `build` |
| 「太素了，活泼一点」 | 换主题 | 建议 `mint-fresh` 或 `warm-orange`，给用户二选一 → 改 → `build` |
| 「要商务正式的」 | 换主题 | `corporate-blue` 或 `swiss-grid` → `build` |
| 「要杂志感」 | 换主题 | `ink-magazine` → `build` |
| 「用我们公司的品牌色，主色是 #0066CC」 | 自定义主题 | 新建 `themes/<公司>.json`（按现有 8 套同构）→ 对比度校验 → frontmatter 引用 → `check` |
| 「照这张图的感觉做」 | 参考图取色 | 读图取主色/辅色 → 建自定义主题 → 说明「只取配色，不复刻版式」 |
| 「有哪些风格可选」 | 浏览 | **出样张**：`preview <deck.md>` 用他自己的封面渲染三套，发图让用户挑（比报名字有效得多）；需要全量清单时才列 8 套名 |
| 「不知道要什么风格」 | 无从判断 | 同上，出三张样张 + 说明「第一行稳重适合汇报、第二行有冲击力适合发布、第三行偏文艺适合分享」 |
| 「换主题之后图不搭了」 | 联动重绘 | `images` 列图位 → 只重绘 `jimeng` 来源的（本地截图不碰）→ `build` |
| 「字体换成宋体」 | 换字体 | 主题 JSON 的 `fonts.family` 改「思源宋体」→ 说明需对方机器有该字体 |
| 「字号都再大一点」 | 整体放大 | 不建议全局加字号（会溢出）。改为 `projection: true`（投屏模式）→ `build` |

## 四、处理配图（高频场景）

**第 1 步永远是 `images <deck.md>`**，拿到图位编号、来源、路径清单。

| 用户原话 | 意图 | agent 动作 |
|---|---|---|
| 「第三页那张图不好看，重画」 | 单张重绘 | `images` 找 `P3-图1` → 确认来源 `jimeng` → 换 prompt 调即梦 → 改该行路径（**编号不变**）→ `build --pages 3` |
| 「所有配图都不满意，全换」 | 批量重绘 | `images` 列清单 → 只重绘 `jimeng` 来源；`local` 截图先征询「这几张是真实截图，也要换掉吗？」 |
| 「这张图换个风格，要更扁平」 | 换画风 | 原 prompt 加风格词（「扁平/极简/白底/少细节」）→ 重生成 → 换路径 |
| 「图里怎么有字，去掉」 | 修正 prompt | prompt 加负面约束「无文字、无字母、无标签」→ 重生成 |
| 「这张图颜色跟主题不搭」 | 配色协调 | prompt 里写明主题色（如「深蓝色调 #1B4F8A + 橙色点缀」）→ 重生成 |
| 「这页不要图，改纯文字」 | 去图 | 删该图片行 → 换 `title-content` 版式 → `build --pages n` |
| 「加一张图，讲数据增长」 | 加图 | 先 glob 查 `图片/AI/` 有无现成图 → 无则即梦生成 → 插 `![P{n}-图1 数据增长](路径)` → 换 `image-right` → `build` |
| 「图丢了，显示一个框」 | 修缺失 | `images` 看 `缺失!` 项 → 重新生成或改到正确路径 → `build --pages n` |
| 「图太多，页面装不下」 | 减图 | `images` 看该页几张 → 删除次要的，或拆页 |
| 「这个位置放图更合适」 | 调图位置 | 换 `image-left` ↔ `image-right` → `build --pages n` |
| 「图太小了看不清」 | 放大图 | 换 `image-left/right`（图占 46%）或删部分文字；`fit=contain` 保证不裁切 → `build` |
| 「截图被裁掉一部分」 | 图片裁切 | 该图片块指令加 `fit=contain` → `build --pages n` |
| 「产品截图别用 AI 画，用真实的」 | 用真实截图 | 从知识库找截图（glob `**/shot-*.png`）；找不到就请用户提供 |

**重绘铁律**：
1. 编号 `P{页}-图{序号}` 是图位永久身份，**换图不换号**
2. 旧图不删（用户可能反悔）
3. `local` 来源（真实截图）重绘前必须问用户——AI 画不出真界面

## 四b、迭代阶段（内容稿 / 交付稿，最常用）

用户改内容要来回几轮。**每轮都跑完整验收会让体验崩坏**——所以要分两档。

| 档位 | 命令 | 耗时 | 查什么 | 话术关键词 |
|---|---|---|---|---|
| 纯标题 | `check` | 秒级 | 容量/大纲/结构/密度 | 「先看叙事线」 |
| **内容稿** | `render` + `qa --no-vision` | **约 8 秒** | 重叠/裁切/溢出/字号/密度 | 「内容稿，还没最终验收」 |
| **交付稿** | `build` | 3-5 分钟 | 上面全部 + 审美 + 五维 | 「最终稿，可以直接用」 |

### 用户怎么说 → 走哪档

| 用户原话 | 意图 | agent 动作 |
|---|---|---|
| 「先别生成，我们先把内容改好」 | 要内容稿 | `render` + `qa --no-vision`，交内容稿 + 话术 |
| 「我想先看文字，排版后面再说」 | 要内容稿 | 同上；先给 `-outline.md` 标题清单让他扫 |
| 「内容还没定，别急着做」 | 要内容稿 | 同上 |
| 「先给我个大纲，满意了再做」 | 要纯标题 | 只跑 `check`，发幽灵稿（纯标题，无正文） |
| 「第 5 页那句话改一下」 | 微调 | 改 md → **内容稿**（8 秒）→ 交回 |
| 「这页再精简一点」 | 微调 | 同上 |
| 「嗯……还是不太对，再改改」 | 第 N 轮微调 | 同上，**不要升级到 build** |
| 「这版可以了」「出成品」「就这样」「发我」 | 定稿 | `build`（完整验收，3-5 分钟） |
| 「给我个 PDF」 | 定稿 + 导出 | 先 `build`，再 `pdf` |

### 交内容稿的标准话术（三句话，各解决一件事）

> 改好了，你先看这版 —— **这是内容稿，还没做最终排版验收**。
> 你确认内容没问题，我再跑一遍完整检查（大概两三分钟），出正式交付稿。
>
> 现在要改哪一页？

- 「这是内容稿」→ 用户知道可以大胆改
- 「还没做最终验收」→ 用户不会拿草稿去汇报
- 「确认后我再跑」→ 给出定稿的明确触发点，且预告会变慢

### 交交付稿的话术

> 内容定稿了，完整验收跑完：N 页全部通过 —— 几何层面无重叠、无裁切、字号可读，
> 视觉评分 XX-XX。这版是最终稿，可以直接用。

### 反例

> ❌ 每轮都 `build`：用户改一行字等 3 分钟，改五次等五轮 → 体验崩坏
> ✅ 内容稿 8 秒一版，改到满意才定稿

> ❌ 「已经生成好了，你看看」（不说版本性质）→ 用户以为是成品，拿去汇报发现排版没验
> ✅ 「这是内容稿，你确认后我再出最终稿」

> ❌ 只说「这个还没验收」→ 用户不知道该不该信
> ✅ 说清差什么（视觉审美）+ 什么时候补（确认内容后）

### 内容稿阶段为什么仍跑几何自检

只 `render` 是 2 秒，但用户可能看到字溢出、元素重叠的烂版面，直接失去信任。
多花 6 秒跑 `qa --no-vision` 挡住硬伤——**这些硬伤大多是内容量问题**（字太多、要点太长），
正好是内容阶段该发现的。审美问题留到定稿。

## 五、交付形态

| 用户原话 | 意图 | agent 动作 |
|---|---|---|
| 「给我个 PDF，我要发邮件」 | 导出 PDF | `pdf <deck.html> -o <名>.pdf` |
| 「要一份带备注的复盘稿」 | 备注版 PDF | `pdf --annotations`（每页底部印演讲备注） |
| 「我看看效果」 | 预览 | `build --open` 直接打开 |
| 「会议室要投屏，坐后排看不清」 | 投屏模式 | frontmatter 加 `projection: true`（字号下限抬高、容量自动收紧 35%）→ 提醒「投屏时按 F 全屏」 |
| 「手机上也要能看」 | 移动端 | 说明手势已支持（左右滑动翻页）；`--open` 让用户手机访问 |
| 「要打印出来发纸质」 | 打印 | `pdf` 导出后打印；或浏览器 Ctrl+P（打印样式已适配：一页一张） |
| 「能发微信吗」 | 分发 | 说明单文件 HTML 可直接发（图片已内嵌），也可发 PDF |
| 「文件太大了」 | 体积 | 用 `--no-embed` 图片外链（需连图一起发）；或压缩配图分辨率 |
| 「要能离线看」 | 离线 | 单文件 HTML 天然离线（无外部依赖） |
| 「怎么翻页」 | 用法 | 方向键 / 空格 / 点击 / 滚轮 / 手机滑动；N 备注、F 全屏、P 打印 |

## 六、模糊表达怎么澄清

用户常常说不清，先问一句再动手（一次问全，不要挤牙膏）：

| 模糊原话 | 澄清问题 |
|---|---|
| 「再高级一点」 | 是指配色更沉稳（换深色主题）、还是留白更多（减内容）、还是加装饰（图标/色块）？ |
| 「感觉不对」 | 是内容不匹配（改文案）、还是视觉不好看（换主题/版式）、还是节奏乱（调页序）？ |
| 「太丑了」 | 具体是哪页？`images` 和截图都在，指给我页码我就能定位 |
| 「改改这个」 | 改哪一页、改什么——文字、图、还是版式？ |
| 「多加点内容」 | 加哪一页？加要点还是加数据还是加图？（提醒：一页超 6 条就要拆页） |
| 「专业一点」 | 是要商务风（corporate-blue）、学术严谨（swiss-grid）、还是杂志感（ink-magazine）？ |
| 「跟那个谁的一样」 | 哪个？给个参考图或链接 |
| 「随便，你定」 | 按默认：主题 corporate-blue、密度适中、8-12 页；做完列出我做的选择 |

## 七、边界外怎么回应

| 用户原话 | 回应方式 |
|---|---|
| 「导出成 pptx 发给甲方」 | 说明本技能只出 HTML + PDF；PDF 可直接发（甲方能看不能改）；若必须可编辑的 pptx，建议用办公软件转换并说明会有排版损失 |
| 「帮我美化这份旧 PPT」 | 不在边界内。可以说：把文字内容给我，我用新设计重做一份（走大纲模式） |
| 「加个路径动画 / 陀螺旋」 | 动画白名单封闭；说明支持飞入/淡入/缩放/擦除/脉冲/放大，其余会降级为淡入 |
| 「加个视频」 | 不支持嵌入视频；可放一张封面图 + 链接文字 |
| 「做成可编辑的 pptx 让同事改」 | 同上；或建议同事直接改 md 再重新生成（比改 pptx 更省事） |
| 「这套逻辑改成竖版 4:3」 | 支持：frontmatter `size: "4:3"`；但版式留白按 16:9 设计，可能偏窄 → 先出样张让用户看 |

## 八、一次性大改（用户要推倒重来）

| 用户原话 | agent 动作 |
|---|---|
| 「整个重做，方向不对」 | 问清新方向（受众/场合/核心论点）→ 重写 deck.md（旧文件备份为 `<名>.v1.md`）→ `check` → `build` |
| 「换成另一套故事线」 | 不重写文字，只调页序与标题 → `check` 的幽灵稿给用户确认 → `build` |
| 「压缩到 5 页」 | 只保留每章一张主结论页 → 其余内容移进 notes → `check` 密度 → `build` |
| 「扩到 20 页」 | 每页抽成 2 页（论点 + 展开），或补案例/数据页 → 加 `section` 过渡 → `check` → `build` |

## 九、Agent 自查清单（每次交付前）

**提问闸门（最容易漏，先查这三条）**
- [ ] 闸门 0：用户没给任何内容时，是否**先要内容**（而不是自己编题目、或直接问受众）
