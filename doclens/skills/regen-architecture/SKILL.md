# 项目全貌报告再生成（regen-architecture）

把整个仓库的现状（技术架构、关键节点、流程、接口、模块、数据与持久化）写成一份**给人类读**的报告 `docs/ARCHITECTURE.md`。报告是**构建产物**：每次调用全量重生成、整文件覆盖，不增删合并旧文。

## 何时跑

仅当用户明确要求（重新）生成/更新架构文档或项目全貌报告。普通"讲讲这个项目"类提问不跑本技能——直接口头回答。

## 血泪教训（为什么流程长这样）

单子代理读整域几十个文件会把巨量内容塞进单轮 LLM 请求，请求挂死无响应（2026-10-03 实测：五组直派，70 分钟零进展）。因此：**切组必须先预检机械算、读法必须两遍（骨架先行）、绝不许子代理整域逐文件全文通读**。

## 执行流程（六步，逐步校验完成标准）

### 第 1 步：建提纲

读三处现有文档建立叙事提纲（只做骨架与线索，不照抄内容）：

1. 根 `CLAUDE.md`（架构说明 + 模块边界红线）
2. 根 `CONTEXT.md`（术语表——报告用词必须与它对齐）
3. `docs/adr/` 全部标题（决策索引素材；冲突线索）

**完成标准**：拿到分域清单 + 横切章节清单（见第 4 步结构），并列出 ADR 编号→主题对照表。

### 第 2 步：预检机械切组（必须，不可跳过）

用 glob/`wc -l` 拿**精确文件清单与行数**，然后机械切组：

- 分组按仓库五域起底：doclens 核心（含 tui/ 与 tools/pst-extract）、web_v2 后端、前端 frontend/src、treesearch、planify；
- **每组 ≤30 个常规文件**；>1000 行的文件计 2 个名额；超大文件（如 fts.py 10 万字符级）计 3 个；
- 域内文件多就按子目录切多组（如后端拆 api/ 与支撑模块，前端拆 views+components 与 api+state+utils）；典型总量 10~14 组；
- 每组prompt必须附**该组的精确文件相对路径清单**，禁止只给目录名让子代理自己逛；
- 排除：node_modules / static / 构建产物 / `*.test.ts` / `__pycache__` / egg-info。

切完向用户预告：「共 N 组子代理并发，预计几分钟，期间无消息是正常的（子代理不打日志），请耐心等待」。

**完成标准**：拿到带行数的分组表；每组文件数折算后 ≤30。

### 第 3 步：并发读码（两遍读法，防巨请求）

为所有组**在同一批 task 调用里并发派发**（`agent_type=Explore`，只读）。每子代理 prompt 按此模板（照抄再填空）：

```
为《项目全貌报告》深读以下文件，用两遍读法（严禁逐文件全文通读）：

范围（精确清单，只读这些）：
<该组文件相对路径清单，附行数>

第一遍（骨架）：用 grep 扫每个文件的 class/def/函数签名 + 模块顶部 docstring，
建立模块骨架认知。禁止在第一遍读任何文件全文。

第二遍（枢纽深读）：从清单中挑 ≤15 个枢纽文件（入口、被其他模块高频 import、
数据流必经点），仅对这些文件 read_file 全文或按段读；其余文件停留在骨架层
（签名 + docstring 足以写职责行）。

返回结构化中文笔记（Markdown，总长 ≤2500 词）：
1. 模块清单：每模块一行职责（做什么、依赖谁、被谁用）；
2. 关键函数：仅入口与枢纽（函数名@文件 + 一句话职责 + 在数据流中的位置），
   禁止罗列全部函数；
3. 域内流程：2-4 条主要执行流程（谁触发→经过哪→产出什么）；
4. 对外接口：该组供外部消费的函数/类/事件/端点；
5. 数据与持久化：读写的库表/数据文件（结构、生命周期）；
6. 运行时：常驻线程/子进程（如有）；
7. 文档冲突：源码与 CLAUDE.md/CONTEXT.md/ADR 不符之处（两侧各说什么）。

约束：宁准勿全——笔记超预算时砍函数细节，不砍流程与冲突。不要寒暄。
```

**完成标准**：全部组笔记收齐；某组失败/截断时对该组**缩小组（对半）**补跑一次，仍失败则由你（主代理）直接读该组枢纽文件补齐——不放弃任何域。

### 第 4 步：核实与交叉

- **代码为唯一真相**：笔记与 CLAUDE.md/ADR 冲突时以代码为准写入报告，并在对应位置标注 `⚠ 与 <文档名/ADR 编号> 所述不符：<两侧差异一句话>`。
- 路径引用格式 `文件路径:行号`（行号允许近似）。
- 术语与 CONTEXT.md 对齐（用既定术语，不另造同义词）。
- 接口咬合：前端调的端点 = 后端注册的端点；doclens 调的方法 = treesearch/planify 暴露的方法。咬合不上回头查代码。

**完成标准**：冲突标注落实；接口面交叉核对完成。

### 第 5 步：写报告

覆盖写入 `docs/ARCHITECTURE.md`，章节结构固定：

```
# doclens 架构（项目全貌）

> ⚠ 构建产物：本文件由 regen-architecture 技能全量重生成，勿手改。
> 生成日期：<YYYY-MM-DD>｜基于代码现状，与 CLAUDE.md/ADR 冲突处以代码为准并已标注。

## 1. 全局总览
项目定位、技术栈表、四层分层架构图（graph TD）

## 2. 五域分章（每域结构相同）
职责边界｜模块清单（紧凑表格：模块/职责/关键依赖）｜域内流程（图）｜关键函数（表）｜冲突标注（如有）

## 3. 横切视图
### 3.1 端到端流程
至少四条跨域链路，各配 mermaid 图：一次搜索、一次 AI 对话、一次索引构建、一次日记日总结
### 3.2 对外接口面
REST API 汇总表 + SSE 事件流（watch / chat 各自的事件类型与触发时机）
### 3.3 数据与持久化
ER 图（erDiagram）覆盖：sessions.db（含 kind 体系条目生命周期 stateDiagram）、index.db（documents/FTS5/视觉队列/页表）、
任务板 .tasks/、收件箱 .team/inbox/、机器级 JSON 资产、rewind 备份、ImageStore、pst_attachments
### 3.4 运行时拓扑
后台 Worker 全景图 + 各入口（GUI/TUI/CLI）启动差异 + 启动链路时序图
### 3.5 配置面
三命名空间（CORTEX_/TREESEARCH_/PLANIFY_）关键开关表 + 读取链
### 3.6 测试与架构守卫
test_architecture.py 红线机制、tests/ 布局、前端 Vitest/Playwright
### 3.7 构建与发布
前端 npm run build 产物链、publish-pypi.ps1、双形态分发、start-app.ps1
### 3.8 安全面摘要
每项两三句 + 指向对应 ADR
```

**图形优先铁律**：凡能用图表达的绝不用文字——架构 `graph TD`、流程 `sequenceDiagram`/`flowchart`、数据模型 `erDiagram`、状态机 `stateDiagram-v2`。文字只承载图无法表达的语义。模块/函数清单用紧凑表格。**禁则**：连续两节以上纯文字叙述；超过 10 行的连续文字段落必须重组为图+短段落。

**完成标准**：1~3.8 全部章节齐备；mermaid 语法正确、每图有图题。

### 第 6 步：收尾核验

- 通读全文：五域全覆盖、四条端到端流程齐全、冲突标注落实、术语对齐。
- 报告头部生成日期为当日。
- 向用户汇报：已写入 `docs/ARCHITECTURE.md`、文档-代码冲突清单（如有）、建议跟进事项。

**完成标准**：以上三项做完并向用户交代。

## 约束

- 子代理只读（Explore），不修改任何文件；主代理只写 `docs/ARCHITECTURE.md` 一个文件。
- 报告语言：中文；受众：人类（叙事可读）。
- 关键函数口径：入口、核心数据流枢纽、ADR 点名的机制承载点 + ADR 之后的新重要机制；不做全量函数电话簿。
- 不复述 ADR 正文：细节指向 `docs/adr/<编号>.md`，报告只留两三句摘要与索引。
- mermaid 在 doclens Web UI 预览中不渲染（前端无支持），消费场景是 GitHub/VSCode/IDE——按此预期排版。
