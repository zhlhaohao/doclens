# 文件带问阅读技能（章节并发模式）

用户已指定文件清单（消息中「文件：」一节），无需检索定位。消息中会附带用户对本批文件的具体要求（如「帮我总结第三章」「讲解一下 XX 概念」「XX 人物是干什么的」）；**未提要求时，要求视为「总结全部内容」**（与旧版 summarize-files 行为等价）。

## 执行流程

对每个文件：先 `file_info(path=...)` 探概况（总词数 + 章节清单），再按大小选策略。

### 小文件（全文一次能读完）

直接 `read_document` 全读，然后按用户要求回答（输出格式见下文双轨）。

### 大文件（超单次读取上限 / 章节多）：按章节拆给并发子代理带问阅读

1. 根据 file_info 的章节清单把全文**切成若干组连续的章节**。每组词数上限以 `task` 工具描述中给出的建议值为准（= 当前模型 max_tokens × 0.8，按 file_info 列出的各章节约略词数累加估算，为子代理的笔记输出留余量；**严禁**把超限的一大章连带子节整组丢给一个子代理——超载会导致笔记被 max_tokens 截断、靠后的章节整段丢失）。
2. **在同一条消息里为每组章节发起一个 `task` 工具调用**（系统会并发执行这些子代理），`agent_type` 用 `Explore`。每个子代理的 prompt 按此模板写（用户要求**原文照抄**，不要转述）：

```
阅读知识库文件「<相对路径>」的以下章节，针对下述用户要求提取相关内容：

用户要求：<用户要求原文；未提要求时写「总结全部内容」>

- <章节标题 1>（必须与 file_info 目录清单完全一致）
- <章节标题 2>
...

步骤：
1. 用 read_document(path="<相对路径>", section="<章节标题>") 逐章精读；
   单章超输出上限时按提示用其子章节或 start_word/end_word 续读。
2. 逐章判定与用户要求的相关性，只返回以下结构的笔记（不要寒暄、不要任务过程描述）：

### <章节标题>
- 与要求相关的要点（保留关键数据、结论、术语、原文表述）
...

或（该章与要求完全无关时）：

### <章节标题>
- （本章与要求无关）

硬性要求：
- 上面列出的每一章都必须有对应小节（相关要点或无关声明），一章都不能缺。
- 相关章节的笔记要**详实**：保留公式、数值、参数、术语、结论的原文表述；
  宁详勿略，禁止每章只写一两句概括——你的笔记是主代理回答的唯一信息源，
  笔记里丢掉的内容不会出现在最终回答里。
- 无关判定要诚实：不确定相关与否时按相关处理（返回要点），不要轻易标无关。
```

3. **校验覆盖度**：
   - **结构硬校验**：逐组核对返回笔记是否覆盖分配的每一章（相关要点**或**无关声明均可）。发现缺章、笔记被截断或子代理报错（如误报"没有 read_document 工具"）时，**为缺失部分重新发起一个 task 补跑**（可缩小分组），不要放弃这些章节。
   - **点名章节不许无关**：用户要求中明确点名的章节（如「第三章」，按 file_info 目录清单对号）返回了「无关」时，对该组补跑一次。
   - **全组无关先补跑再死心**：用户点名的人物/概念在整个文件**所有组**都返回无关时，先补跑一次（子代理 prompt 中明示关键词，要求逐章扫描关键词后再判定）；补跑仍全无关 → 如实回答「未在该文件中找到相关内容」，**不编造**。
4. 收齐（含补跑）所有子代理笔记后，由你（主代理）按要求组织最终回答（见输出格式）。

### 会话内追问（省略重复执行）

同一会话中追问时，上文已有该文件的章节笔记且追问**未改变要求方向**的：复用上文笔记，仅对新点名或未覆盖的章节定向补读（可由你直接 read_document，或发起单个子代理）；追问改变了要求方向（涉及新的人物/概念/全局梳理）时，重新走上面的全流程。

### 多文件

所有文件的全部章节组在**同一批** task 里并发派发（跨文件同批，不逐文件串行）。输出仍逐文件组织；总结类要求在文件间存在可比性时最后追加「## 共同点与差异」；跨文件比较/关联类要求由要求本身驱动组织（属自由组织轨）。

## 输出格式（双轨）

**总结/提炼类要求（含未提要求时的默认）**——沿用固定结构，每个文件一节：

```
## <文件名>

### 核心论点
- ...

### 关键数据 / 事实
- ...

### 结论 / 值得注意的点
- ...
```

- 要点数量与原文规模匹配：大文档（>5000 词）每节可达 10+ 条，并在三节之后追加「### 分章要点」，按章节列出各章核心内容。
- **合并 = 结构化拼接 + 去重，不是二次压缩**——最终总结的信息量不应少于子代理笔记之和；笔记中的公式、数值、结论要点应尽可能保留进最终总结。
- 无关声明的章节在总结类要求下不应出现（要求即总结，每章都相关）；若出现，按覆盖度校验的「点名章节」规则处理。

**其他要求（讲解概念 / 梳理人物 / 问答等）**——按用户要求自由组织回答的形态与结构，遵守三条硬约束：

- 以子代理笔记为唯一信息源，不编造文件中不存在的信息；笔记与原文冲突时以原文为准。
- 忠实原文表述：讲解/梳理中的事实、数据、称谓以笔记保留的原文为准，不演绎。
- 正文提及文件时**直接写它的相对路径**（如 `医疗/癌症治疗.md`）——系统会从正文提取真实路径构建引文，无需手写「## 参考资料」章节。

## 约束

- 只处理清单内文件，不主动扩展读取其他文档；子代理只读（Explore），不修改任何文件。
- 子代理可用工具：`file_info` / `read_document` / `read_file` / `bash`。二进制格式（PDF/DOCX/PPTX/XLSX）**必须走 read_document**，禁止 read_file 读二进制（会得到乱码）。
- section 标题**必须取自 file_info 的目录清单**，禁止臆造；找不到时用 file_info 重新核对。
- 无章节结构的纯文本大文件：按 file_info 的总词数切成若干词区间（每段长度同样不超过 task 工具描述中的每组建议词数上限），子代理用 start_word/end_word 分段读，笔记小节头写「### 词区间 <start>-<end>」。
- **不做检索定位**：本技能不使用 search_kb/kb_grep——相关章节的发现交给子代理带问阅读完成，防止检索召回缺口漏掉内容（「查一个人物也全书并发」是有意取舍：以并发成本换零漏读）。
- 内容以原文为准，不编造文件中不存在的信息；子代理笔记与原文冲突时以原文为准。
