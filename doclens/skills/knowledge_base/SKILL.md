# 知识库技能

## 工具

- **search_kb**: FTS5 全文检索文档片段（自然语言关键词，自动中英文分词）。返回 XML（`<meta>` 含路径/层级 + `<content>`）。**结果用于回答必须加引文**。可选 `paths` 缩小范围：相对目录（如 `"科技"`）或相对文件路径（如 `"科技/量子计算.md"`）的数组。
- **kb_grep**: 知识库内正则搜索文档内容（含未索引文件，能命中 PDF/DOCX 等已索引二进制文档的解析文本）。`search_kb` 无结果或需精确匹配（代码/正则模式）时用。结果 `<path>` 可直接传给 `read_document`。可选 `paths` 同 search_kb。
- **file_info**: 单文件概况探查（大小/总词数/章节数/章节清单/修改时间），**不返回正文**。**read_document 之前先调它**：判断文件规模、挑选 section 或词区间，避免盲读浪费 token。
- **read_document**: 读文档完整/部分内容（md/pdf/docx/pptx/xlsx/html/代码等）。**结果用于回答必须加引文**。
- **manage_kb**: 索引管理（`reindex` 重建 / `stats` 统计）。reindex 仅限索引损坏/语料更新后，非常规重试手段。

## ⚠️ 回答铁律（最高优先级）

只要调用了 `search_kb` / `read_document` / `kb_grep` 任一回答用户，回答**必须同时**：

1. **正文标注**：引用处插 `[N]`（如 `[1]`、`[1][2]`），紧跟陈述、标点前。
2. **末尾引文**：追加 `## 参考资料`，每条 `1.` `2.` 编号（**不用 `[N]` 作列表前缀**），内容**只写相对 workdir 的文档路径**（如 `生命科学/xxx.md`）。
   - **格式约束**：路径**禁止** markdown 链接 `[text](url)`、**禁止** `file://` 绝对 URL、不含 `<hierarchy>` / 行号。违反 → 用户点击"打不开"。
   - `search_kb`/`kb_grep` 取 `<path>`；`read_document` 取 `文档:` 行后路径。同一文档只列一次，保持顺序。
   - **只引用答案内容实际来源的 `<result>`**：答案的数据/结论来自哪条命中就引哪条的 `<path>`；与答案无关的命中**禁止罗列**（宁缺毋滥）。正文每个关键论点都必须能在所引文档中找到依据。

用了上述工具却没有 `## 参考资料` = 不合规，补齐再输出。流程性回复（reindex/stats 提示）除外。

**回答前自检**：用了工具？正文有 `[N]`？末尾有 `## 参考资料` 且路径是纯相对路径？同一文档只列一次？

**示例**：
```
量子计算利用量子比特进行信息处理 [1][2]。

## 参考资料
1. 量子计算导论/第一章.md
2. 量子计算导论/第二章.md
```

## 机器解析契约（系统强制）

系统会**机器解析**「## 参考资料」章节并**校验路径是否存在**；不合规时将改用工具检索结果兜底并向用户告警（不再重答）。严格遵循：

1. 章节标题必须正好是 `## 参考资料`（两个#、空格、"参考资料"四字）
2. 每行 `数字. 路径`（如 `1. 量子计算/第一章.md`），数字后一个点一个空格
3. 路径 = 纯相对路径，禁止 `[t](u)` / `file://` / 行号 `:数字` / `<...>`
4. 用了 `search_kb`/`kb_grep`/`read_document` 必须有本章节；路径必须真实存在

## 指定范围模式（消息含「文件：」清单时）

用户从文件列表勾选文件/目录后调用本技能时，消息带「文件：」清单一节（相对路径，**文件与目录可混合**）。此时问答范围**限定在清单内**：

1. **检索必带 `paths`**：`search_kb` / `kb_grep` 调用必须传 `paths=[清单原样数组]`（目录与文件条目都合法），只在清单范围内搜。
2. **清单中的具体文件**：可直接 `file_info` → `read_document` 深读。
3. **清单中的目录**：目录不能 `read_document`——先 `search_kb(query, paths=["该目录"])` 定位其中文档，再对命中文档 `file_info` / `read_document`。
4. 引文规范不变（`## 参考资料`，路径仍是相对 workdir 的文档路径）。
5. 清单内找不到答案时，明说"所选范围内未找到相关内容"，**不得**改用清单外内容回答（除非用户后续明确放开范围）。

## 搜索策略（先规划，后检索，有预算）

### 第一步：查询规划（调用工具前先完成）

`search_kb` 是 FTS5 **精确关键词匹配**，非语义检索，单次查询易漏。检索**之前**先生成 3~6 个互相独立的查询，覆盖不同角度：
- 核心实体/专名（人名、产品名、项目代号、文件名）
- 同义词/近义词替换
- 上下位词展开（如"慢性病"→"糖尿病""高血压"）
- 领域术语/行话
- 中英文互换
- 长句切分为短词组合

### 第二步：并行批量检索

**同一轮并行发出全部独立的 `search_kb` 调用**（互不依赖，本地 FTS 很快）。多查询结果去重合并。

### 第三步：宽到窄，命中即深读

有命中：`file_info` 探概况（规模/章节清单）→ `read_document` 精读关键章节（`section="第三章 实验方法"` 返回该节及子节点；或 `start_word/end_word` 按词序号读，如 `start_word=100, end_word=300`）。
无命中：`kb_grep` 补搜（精确字符串/正则），命中后同样 `file_info` → `read_document`。

### 检索预算与止损（强制）

- **预算**：`search_kb` + `kb_grep` 合计约 **6 轮**仍无有效结果 → **停止检索，如实回答"知识库中未找到相关内容"**，可一句话说明已尝试的角度，**不得**编造内容。
- **收敛即停**：已获得的命中足以支撑答案时立即作答，不追求"完美"结果、不做确认性重复检索。
- **禁止换汤不换药**：每一轮新查询必须引入**新的角度**（新实体/新语言/新词位），不得用语义相同的近义查询反复重试同一角度，否则视为消耗预算。
- **reindex 不是重试手段**：仅当怀疑索引损坏或语料刚更新时才 `manage_kb(action='reindex')`，且单次问答至多一次。

`search_kb` 调用示例：`search_kb(query="机器学习 深度学习", max_results=10)`；限定范围：`search_kb(query="机器学习", paths=["科技", "编程/ai.md"])`

## 多格式读取

- PDF/DOCX/PPTX/XLSX 等二进制格式**必须用 `read_document`**（非 `read_file`）
- `section` 按章节标题定位（多层嵌套结构完整提取）；`start_word/end_word` 按词序号读（1-based 闭区间；**中日韩文字每字算一词**，英文/数字按空白切分；输出标注当前词位置与总词数，截断时按提示的 start_word 续读）

## 边界（强制）

**仅用于内部知识库问答**。**禁止**：`Task` 子代理（脱离上下文 + 自带外部工具）、`webfetch` / web 搜索 / `bash` 联网。仅用上述 5 个工具在本地作答。无结果时按「检索预算与止损」如实告知用户未找到（不无限重试、不把 reindex 当默认动作），**不转向外部搜索**。
